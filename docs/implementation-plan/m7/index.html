Milestone 7 · Durability

Compaction

When the context window fills, summarize and continue. The harness compresses the long tail of tool results and intermediate messages into a structured summary, retains the most recent turns verbatim, and the session keeps going. Indefinite-length sessions become real.

Why M7 is the last harness-capability milestone

M1–M6 deliver a working agent. M7 is the difference between an agent that works for thirty minutes and one that runs all afternoon. The mechanism is small and well-scoped, but unlocks the daily-driver experience — right before we shift to network and GUI adapters.

arnes-core::compact

// arnes-core/src/compact.rs

pub struct Compactor {
    pub trigger_ratio: f32,        // default 0.75
    pub keep_recent: usize,        // default 6
    pub summary_prompt: Cow<'static, str>,
    pub model_window: u32,         // tokens; configured per-model
}

impl Compactor {
    pub fn should_compact(&self, history: &[Message]) -> bool;
    pub fn approx_tokens(&self, history: &[Message]) -> u32;

    pub async fn run(
        &self,
        history: &[Message],
        runner: &AgentRunner,
        progress: ProgressSink,
    ) -> Result<Compacted>;
}

pub struct Compacted {
    pub summary_text: String,
    pub kept_recent: Vec<Message>,
    pub original_message_count: usize,
    pub tokens_freed: u32,
}

pub struct CompactionEntry {
    pub id: Uuid,
    pub timestamp: u64,
    pub summary_text: String,
    pub original_message_ids: Vec<Uuid>,
    pub kept_message_ids: Vec<Uuid>,
    pub tokens_freed: u32,
}

Token estimation

Two sources contribute. The session's running CumulativeUsage (M1) carries actual input-token counts reported by the provider for prior turns — far more accurate than any heuristic. For the about-to-be-sent user message we still need an estimate. A TokenCounter trait lets the two combine, and lets us swap in real tokenizers later without rewriting Compactor. 

pub trait TokenCounter: Send + Sync {
    fn count(&self, history: &[Message]) -> u32;
}

pub struct CharsHeuristicCounter;
impl TokenCounter for CharsHeuristicCounter {
    fn count(&self, history: &[Message]) -> u32 {
        let chars: usize = history.iter().map(|m| m.char_len()).sum();
        ((chars + 3) / 4) as u32
    }
}

In practice the trigger combines both: prior turns' actual input tokens summed across the session's CumulativeUsage buckets (each bucket's tokens.input) + heuristic estimate of the pending user message + a small constant for tool declarations and the system prompt. The heuristic-only fallback applies when no prior turn has run yet.

When to trigger

Three conditions must hold simultaneously:

  1. Token estimate ≥ model_window * trigger_ratio.
  2. The session is between turns. Specifically: not in the middle of a tool_use / tool_result pair. Compacting mid-turn breaks the protocol — the model has emitted a tool call and is waiting for its result; cutting that pair leaves the next turn malformed.
  3. The most recent message is a user message (we are about to start a new turn). This is the canonical safe point.
Compaction is per-agent. The trigger evaluates one agent's history against that agent's model window. V1 only ever runs the root agent so this is invisible. Post-V1 sub-agents each maintain their own history and compact independently. Compactor::should_compact takes an &AgentHistory (single-agent slice) from V1 onward, even though V1 only ever passes the root's slice — same reasoning as elsewhere: the function signature stays right so the post-V1 expansion is additive. 
impl Session<F, E> {
    pub async fn prompt(&mut self, input: String) -> Result<()> {
        self.history.push(Message::user(input));

        if let Some(c) = self.compactor.as_ref() {
            if c.should_compact(&self.history) {
                self.run_compaction().await?;
            }
        }

        // ... rest of the turn ...
    }
}

The summary prompt

Compaction quality is summary-prompt quality. Asking for structured output — not free text — reliably preserves the right things. 

pub const DEFAULT_SUMMARY_PROMPT: &str = r#"
You are about to be replaced by a fresh instance of yourself, which will
inherit the summary you produce now instead of the full transcript.

Produce that summary now. Include, in this order:

1. THE GOAL: What is the user trying to accomplish? One short paragraph.
2. KEY DECISIONS: Concrete decisions made so far (chosen approach, rejected
   alternatives, important constraints). Bullet list.
3. STATE OF THE WORLD: Files read / edited / created with paths; commands
   run with outcomes; anything else the new instance needs to know about
   the state of the project. Bullet list.
4. OPEN QUESTIONS: Anything raised and not resolved. Bullet list.
5. NEXT STEP: What is the very next action the new instance should take?
   One sentence.

Be specific. The new instance has none of the original context; assume it
will only know what you write here.
"#;

Rewriting the history

async fn run_compaction(&mut self) -> Result<()> {
    let compactor = self.compactor.as_ref().unwrap();
    let original = self.history.clone();

    // Ask the model to summarize.
    let compacted = compactor.run(&original, &self.runner, self.progress()).await?;

    // Notify the frontends BEFORE rewriting state.
    self.frontend.on_event(SessionEvent::Compacted {
        message_count: original.len(),
        tokens_freed: compacted.tokens_freed,
    }).await;

    // Rewrite in-memory state.
    self.history = vec![
        Message::user_synthetic(&format!(
            "[compaction summary] The previous transcript was compacted to fit the \
             context window. The summary below stands in for it.\n\n{}",
            compacted.summary_text
        )),
    ];
    self.history.extend(compacted.kept_recent);

    // Persist the compaction event to disk; original messages stay in the JSONL.
    if let Some(w) = self.writer.as_mut() {
        w.append(SessionRow::Compaction(CompactionEntry {
            id: Uuid::now_v7(),
            timestamp: now_unix(),
            summary_text: compacted.summary_text,
            original_message_ids: /* IDs of compressed messages */,
            kept_message_ids: /* IDs of preserved messages */,
            tokens_freed: compacted.tokens_freed,
        })).await?;
    }
    Ok(())
}

Critical: the JSONL on disk is not rewritten. Original messages remain in the file. The compaction row records that an in-memory reorganization happened. Future --continue semantics: resume from the in-memory representation as of the last compaction, not from a replay of every original row. The full history is always recoverable for inspection.

In-memory state shrinks; the file on disk only grows. Compaction is a marker, not a rewrite.

Surfacing compaction

TUI at M7
  • A subtle one-line notice in the transcript: "[compacted: 28 messages → 7, freed ~158k tokens]".
  • /compact slash command to trigger manually before the threshold.
  • Optional /inspect command to view the summary the model produced.
ACP at M7
  • Emit a session/update notification with a custom _meta field carrying compaction info. Editors that understand it can render a marker; those that don't, ignore it.
  • No new method — intentionally minimal protocol surface.

Resume semantics revisited

Loading a session that contains compaction rows is more involved than M6:

  1. Read all rows top to bottom.
  2. Find the last Compaction row.
  3. Rebuild in-memory history as: synthetic summary message + kept_message_ids (looked up in the message rows).
  4. Apply any messages that came after the last compaction row verbatim.

load_session from M6 grows this behaviour. A flag load_full = true lets debug tooling rebuild the original full history (every message, ignoring compactions) for inspection.

Implementation tasks

  1. Create arnes-core::compact with Compactor, TokenCounter, Compacted, CompactionEntry.
  2. Add SessionEvent::Compacted variant.
  3. Extend SessionRow with Compaction variant (the format actually grew at M6 for this; M7 finally writes the variant).
  4. In Session::prompt: top-of-method check; if compacting, call run_compaction before continuing.
  5. Implement run_compaction: ask the model via a fresh agent-rig call with the summary prompt; await; rewrite in-memory history; emit event; append disk row.
  6. Extend load_session to honour compaction rows; add the load_full debug flag.
  7. TUI: render the notice on SessionEvent::Compacted; /compact slash command calls Session::compact() public API.
  8. ACP: emit session/update with _meta field on Compacted.
  9. CLI: --compaction-ratio and --keep-recent override flags; --no-compaction disables (debug only).

Testing checklist

  • Trigger correctness: token counter under threshold → no compaction; over threshold → compaction. Edge: mid-tool turn must not compact even when over threshold.
  • Summary structure: scripted LLM returns a known structured summary; assert in-memory state rewrites correctly with summary + last K turns.
  • Round-trip after compaction: write a session through one compaction; close; load; assert the loaded in-memory state matches what was active when closed.
  • load_full debug: same file loaded with the flag returns every original message ignoring the compaction.
  • Repeated compaction: drive a session through two compactions; ensure the second compresses the first's summary plus the intervening tail without errors.
  • ACP _meta: assert the outbound notification has the expected shape; assert a hand-written client that ignores _meta still functions.

Risks specific to M7

  • Summary loses load-bearing detail. If the summary says "use snake_case" but not where, the next instance forgets. The structured prompt mitigates; the only real fix is improving the prompt iteratively.
  • Cascading compactions degrade quality. Each pass is lossy; three passes is summarizing summaries of summaries. For sessions that compact more than twice, consider surfacing a "long session, consider starting fresh" hint to the user.
  • Mid-turn compaction. The check is between-turn; a stray code path could break this. Add an assertion at the top of run_compaction that the last message is a user message and emit a loud error if not.
  • Token estimate drift. The 4-chars heuristic gets worse with code-heavy content. Watch for over-aggressive triggering; consider per-model overrides.

End state of M7

A multi-day coding session does not hit a context wall. Compaction happens automatically at threshold; surfaces as a one-line notice in the TUI and a _meta tag in ACP session/update; the JSONL on disk retains the full history for inspection. With M1 through M7 done, arnes is functionally complete as a daily-driver coding agent.
