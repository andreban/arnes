Milestone 8 · Networked

HTTP / WebSockets adapter

Mount arnes behind a single axum server: REST routes for request/response shapes, a WebSocket route per session for streaming. Designed so that ACP-over-WS slots in as a second route tree the moment upstream lands the transport spec.

Why M8 after the harness is complete

With M1–M7 done, the harness is a finished daily-driver. M8 is the first milestone aimed at other people's machines — remote agents, headless CI, browser UIs. We do this only after the local story is solid, so the network surface inherits a working core rather than exposing a half-built one.

WebSocket frame vocabulary

The frame types align deliberately with ACP's session/update variants so a future ACP-over-WS handler can share most of the encoding logic.

Client → server

{ "type": "prompt", "content": [ { "type": "text", "text": "..." } ] }
{ "type": "cancel" }
{ "type": "set_mode", "mode": "ask" }
{ "type": "permission_response", "id": "...", "decision": "allow" | "deny" | "always_allow" }

Server → client

{ "type": "agent_message_chunk",   "text": "..." }
{ "type": "agent_thought_chunk",   "text": "..." }
{ "type": "tool_call",             "id": "...", "name": "bash", "input": {...}, "status": "pending" }
{ "type": "tool_call_update",      "id": "...", "status": "running"|"completed"|"failed", "result"?: {...} }
{ "type": "permission_request",    "id": "...", "tool": "bash", "input": {...}, "summary": "..." }
{ "type": "turn_end",              "stop_reason": "end_turn", "usage": { ... } }
{ "type": "session_usage",         "cumulative": { ... } }   // cumulative after the turn
{ "type": "compacted",             "tokens_freed": 158000, "message_count": 28 }
{ "type": "error",                 "message": "..." }

HttpFrontend

// arnes-http/src/frontend.rs

pub struct HttpFrontend {
    tx: mpsc::UnboundedSender<ServerFrame>,
    pending_perms: Mutex<HashMap<Uuid, oneshot::Sender<Permission>>>,
}

#[async_trait]
impl Frontend for HttpFrontend {
    async fn on_event(&self, ev: SessionEvent) {
        let _ = self.tx.send(ev.into_server_frame());
    }

    async fn request_permission(&self, req: PermissionRequest) -> Permission {
        let id = Uuid::now_v7();
        let (resp_tx, resp_rx) = oneshot::channel();
        self.pending_perms.lock().await.insert(id, resp_tx);
        let _ = self.tx.send(ServerFrame::PermissionRequest { id, req });
        match tokio::time::timeout(Duration::from_secs(120), resp_rx).await {
            Ok(Ok(p)) => p,
            _ => Permission::Deny,  // timed out or socket dropped
        }
    }
}

One HttpFrontend per WebSocket connection. If the socket drops mid-flight, in-flight permission requests time out and become denies; the session itself stays alive (the client can reconnect via a fresh WS upgrade and re-attach).

SessionRegistry

// arnes-http/src/registry.rs

pub struct SessionRegistry {
    sessions: DashMap<Uuid, Arc<Mutex<Session<HttpFrontend, LocalHost>>>>,
    busy:     DashMap<Uuid, ()>,  // session id is here while a prompt is in flight
    idle_timeout: Duration,
}

impl SessionRegistry {
    pub fn create(&self, opts: NewSessionOpts) -> Result<Uuid>;
    pub fn get(&self, id: Uuid) -> Option<Arc<Mutex<Session<...>>>>;
    pub fn delete(&self, id: Uuid) -> Result<()>;

    /// Try to mark busy. Returns Err(Conflict) if already busy.
    pub fn try_acquire(&self, id: Uuid) -> Result<BusyGuard>;

    /// Background task: evict idle sessions.
    pub fn spawn_gc(self: Arc<Self>);
}

One Session may have multiple attached WebSocket viewers (read-only), but only one writer. POST .../prompt and WS prompt frames both call try_acquire; concurrent calls get 409 Conflict.

Auth and CORS

V1 auth: single bearer token configured at server start. Every request (including WS upgrade) must carry Authorization: Bearer <token>; mismatch returns 401. The /healthz endpoint is the only exception. 

let app = Router::new()
    .route("/healthz", get(health))
    .nest("/v1", v1_router())
    .layer(tower_http::cors::CorsLayer::new()
        .allow_origin(cli.cors_origins)        // explicit allow-list
        .allow_methods([Method::GET, Method::POST, Method::DELETE])
        .allow_headers([AUTHORIZATION, CONTENT_TYPE]))
    .layer(middleware::from_fn_with_state(state.clone(), auth_middleware))
    .layer(tower_http::trace::TraceLayer::new_for_http());

No TLS in the binary. Operators run the server behind a reverse proxy (caddy, nginx, traefik) that terminates TLS. Document this prominently.

Hook for ACP-over-WS (deferred but designed in)

When upstream lands the ACP transport spec, we add a second route tree: 

let app = app.route("/acp/ws", get(acp_ws_upgrade));

async fn acp_ws_upgrade(ws: WebSocketUpgrade, State(registry): State<...>) -> Response {
    ws.on_upgrade(|socket| async move {
        let (tx, rx) = json_rpc_framing_over_ws(socket);
        // Hand the channel to the SAME router that arnes-acp uses for stdio.
        arnes_acp::serve(tx, rx, registry).await;
    })
}

Because arnes-acp's router is transport-agnostic, the handler code is unchanged. Only the framing differs.

Host in HTTP mode

V1: LocalHost. The server has full local-filesystem and process access. Suitable for self-hosted single-trust-boundary deployments. Documented limitation: do not expose arnes-serve to untrusted users without a sandboxed Host impl (out of scope for V1).

Implementation tasks

  1. Create the arnes-http crate; add axum and tower-http as deps.
  2. Implement SessionRegistry with per-session locking, idle GC.
  3. Implement REST routes (sessions CRUD, prompt, cancel, compact, tools, skills, healthz).
  4. Implement WS upgrade and frame serialization. Define the server-side ServerFrame enum mirroring SessionEvent with the permission_request addition.
  5. Implement HttpFrontend with the pending-permissions map and oneshot reply channel.
  6. Auth middleware (constant-time token compare); CORS layer; trace layer.
  7. Add a main.rs to arnes-http so it produces the arnes-serve binary. Flags: --bind <addr>, --token <t>, --cors-origin <origin>, plus the shared CommonOpts.
  8. Write an example browser page (~150 lines of HTML+JS, dropped under examples/) that connects to the WS and renders a basic transcript. Useful for smoke testing; not shipped as a real GUI.
  9. Integration test: spin up the server in-process; make REST calls with reqwest; connect WS with tokio-tungstenite; drive a scripted scenario end-to-end.

Testing checklist

  • Routes: happy path on every endpoint; 401 without token; 404 for missing session; 409 on concurrent prompt.
  • WS: upgrade succeeds with token; prompt frame triggers stream of update frames; permission round-trip works.
  • Cancel: POST /cancel mid-prompt; verify the WS receives a cancel/error frame and the registry releases the busy lock.
  • Idle GC: spin up sessions, advance time, verify eviction.
  • CORS: request from disallowed origin rejected; allowed origin succeeds.
  • Auth timing: constant-time compare (no measurable timing difference between mismatched tokens of equal length).
  • Reconnect: drop the WS mid-stream; reconnect with the same session id; verify the session is still alive.

Risks specific to M8

  • Long-running prompts vs HTTP timeouts. Reverse proxies often kill idle HTTP connections after 30–60s. The non-streaming POST .../prompt may exceed this. Document recommended proxy settings; suggest WS for any prompt expected to last more than a few seconds.
  • Backpressure on the WS. If a client falls behind on event consumption, the unbounded channel grows. Bound the channel (1000 frames?) and disconnect slow clients.
  • Permission timeouts. 120s default is arbitrary. Make configurable; reaching the timeout should surface a clear error frame.
  • Server crash mid-prompt. The JSONL log captures messages turn-by-turn; mid-turn loss is OK because partial assistant messages were never appended. Session state survives the crash.

End state of M8

arnes-serve --bind 127.0.0.1:7878 --token $T stays up for a workday. A simple browser page connects via WebSocket and renders a usable transcript. A shell script can spin up a one-shot session with curl. The hook for ACP-over-WS is in place; plugging it in is a small change when upstream is ready.
