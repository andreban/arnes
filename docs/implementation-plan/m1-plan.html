PR #0 — Repo bootstrap

Goal. Stand up the repo with planning docs, meta files, and a clean first commit on main. No Rust yet.

Scope.

  • git init, set up the remote (GitHub default), push the initial commit on main.
  • Copy the planning docs into the new repo: docs/build-your-own-harness/ (the book) and docs/implementation-plan/ (this site). Both stay editable in-tree as the design evolves.
  • README.md — one-paragraph tagline ("arnes is a coding-agent harness in Rust, fronted by a TUI, ACP server, and HTTP/WS server"), one-line install per binary (placeholder until M9), and links to the plan and book under docs/.
  • AGENTS.md — project rules for any coding agent (including arnes itself, eventually) working on the repo: Rust style (rustfmt + clippy -D warnings), toolchain policy (pinned via rust-toolchain.toml in PR #1, no MSRV pin yet), license-header rule (Apache-2.0 + SPDX on every source file), commit-message convention, never commit target/ / .vscode/ / .idea/, where tests live, how to run them.
  • CONTRIBUTING.md — PR process, sign-off requirements (if any), how to run the full test matrix locally, where to file issues.
  • LICENSE — MIT by default unless you prefer Apache-2.0 or dual.
  • .gitignore — standard Rust (target/, Cargo.lock for libraries) plus .vscode/, .idea/, .DS_Store, .env.

Acceptance. Fresh clone shows docs renderable in a browser (open docs/implementation-plan/index.html); README.md answers "what is arnes" in the first paragraph; AGENTS.md is internally consistent with what later PRs commit to (rustfmt, clippy, etc.); the repo is accessible at the chosen remote.

PR #1 — Workspace + CI

Goal. Get to cargo check --workspace passing in CI before any real code lands.

Scope.

  • Root Cargo.toml as a pure workspace (no top-level [package]) with members arnes-core, arnes-tui, arnes-acp. Delete the placeholder src/main.rs from PR #0. No [workspace.dependencies] entries yet — each later PR adds the deps its own code introduces.
  • Empty src/lib.rs in each library crate; placeholder src/main.rs in each binary crate (each carrying the project license header).
  • .github/workflows/ci.yml installing stable via dtolnay/rust-toolchain@stable, then running, in this order: cargo fmt --all -- --check, cargo clippy --workspace --all-targets -- -D warnings, cargo test --workspace. Matrix: Linux, macOS, Windows.
  • Extend the README from PR #0 with a Building & testing section noting "needs a recent stable rustc."

Deliberately deferred. A few files that are conventionally added at workspace-init time would be premature here; the rationale matters because future PRs will be tempted to add them.

  • No rust-version MSRV pin. MSRV is a contract that pays off when publishing a library to crates.io or supporting downstream consumers on varied toolchains. Neither applies yet, so a pin is maintenance overhead (bumping it for every new-stdlib-feature use) without payoff. Revisit when we publish arnes-core or commit to an external support policy.
  • No rust-toolchain.toml. Pinning channel = "stable" only auto-installs stable for rustup users who don't already have it — tiny convenience, no reproducibility (different days = different "stable"). CI declares its toolchain explicitly; contributors with an old rustc get a clear "edition 2024 requires rustc 1.85+" error. Pin a specific version here only when we genuinely need reproducible toolchains.
  • No rustfmt.toml / clippy.toml. Both files are only useful for overriding defaults. Empty stubs invite bikeshedding without connecting to actual friction. Add a single line to one of them the first time CI surfaces a real disagreement with the defaults — not before.
  • No pre-declared workspace deps. [workspace.dependencies] earns its keep when two or more crates need to agree on a version. Declaring tokio/serde/thiserror/anyhow here, before any crate uses them, is anticipation. PR #2 onward add each dep to [workspace.dependencies] in the same commit that introduces its first use.

Acceptance. CI green; cargo check --workspace clean locally on Linux + macOS + Windows.

PR #2 — Core types: Frontend, Host, Message

Goal. Define the vocabulary the rest of the workspace depends on. No real behavior yet. The type shapes also encode the design's sub-agent commitments from M1 onward.

Scope.

  • arnes-core/src/lib.rs — re-exports.
  • identity.rs — AgentId (enum: Root | SubAgent(Ulid)); ModelKey { provider, model_id }.
  • frontend.rs — Frontend trait; SessionEvent { agent_id, depth, kind: EventKind } with M1's EventKind variants; PermissionRequest/Permission/Scope/Persistence/Principal stubs (real types in M3); FrontendCapabilities.
  • host.rs — Host trait with default Unsupported method bodies; type defs for TerminalSpec, TerminalHandle, DirEntry, TerminalSnapshot; LocalHost unit struct relying on all defaults.
  • tool_context.rs — ToolContext bundling host, progress, cancellation, agent_id, and the spawn_subagent stub (returns unimplemented!() at V1). ProgressUpdate enum with Text and Structured variants.
  • message.rs — Message, ContentBlock (Text variant; ToolUse/ToolResult stubs).
  • error.rs — the crate's error type via thiserror.
  • Doc comments on every public item, including a header comment in identity.rs pointing at core.html § Future-compatibility: sub-agents so anyone touching the type vocabulary sees the design contract.

Acceptance. All public types compile; unit test asserts each LocalHost method returns ErrorKind::Unsupported; cargo doc warns-as-errors clean.

PR #3 — Usage + pricing subsystem

Goal. Token/cost types with three-state pricing (Priced / Free / Unknown), per-(agent, model) aggregation, and a tested registry.

Scope.

  • arnes-core/src/usage.rs — Usage (carries agent_id + ModelKey), Cost, Micros, ModelUsage, CumulativeUsage (indexed by (AgentId, ModelKey)), ModelCostInfo, ModelPricing.
  • arnes-core/src/pricing.rs — PricingRegistry, TOML loader, default + user-override merge logic.
  • arnes-core/data/pricing.toml — seed with the Gemini model(s) M1 uses, plus an Ollama wildcard cost = "free" rule.
  • fn compute_cost(model: &ModelKey, raw_tokens) -> Option<Cost> helper.
  • Wire EventKind::TurnEnd to carry a Usage (signature; emission lands in PR #4).
  • CumulativeUsage::by_model() and by_agent() derived views; tests confirm projections are consistent with the underlying (AgentId, ModelKey) map.

Acceptance. Unit tests cover: three-state behavior (Priced / Free / Unknown), user override wins over default, pattern matching for the Ollama wildcard, CumulativeUsage sum semantics including unpriced-turn counts, per-(agent, model) bucketing (two synthetic Usages with different ModelKeys produce two entries), by_model() flatten correctness.

PR #4 — Session + test scaffolding

Goal. The agent-rig wrapper plus the mocks every later PR will reuse for testing.

Scope.

  • Add agent-rig as a workspace dep (git or path, no provider features yet).
  • arnes-core/src/session.rs — Session<F: Frontend, H: Host> with new(), prompt(), cancel(), cumulative_usage().
  • Translate agent-rig's AgentEvent stream to SessionEvent (text deltas, TurnStart/TurnEnd, usage extraction).
  • arnes-core/tests/support/recording_frontend.rs — captures every event for assertions.
  • arnes-core/tests/support/in_memory_host.rs — fake host (real fs/process impls land in M3).
  • arnes-core/tests/support/scripted_llm.rs — implements agent-rig's LlmModel; replays canned response sequences with known token counts.
  • arnes-core/tests/session_roundtrip.rs — two-turn round-trip; asserts event order, history accumulation, cumulative_usage growth.

Acceptance. session_roundtrip passes deterministically without any API key. cumulative_usage() after two turns equals the sum of per-turn usage values from the scripted LLM.

PR #5 — ACP transport spike (jsonrpsee)

Goal. Bidirectional JSON-RPC over stdio works; the library decision is made and recorded.

Scope.

  • arnes-acp/src/transport/stdio.rs — jsonrpsee server on stdin/stdout, configured for bidirectional dispatch.
  • arnes-acp/src/transport/json_rpc.rs — outbound-call helper to validate the server-initiated request path (any stub method, even an unimplemented fs/read_text_file).
  • Stub method registry: any unknown method returns -32601 Method not found.
  • ADR: docs/adr/0001-jsonrpc-library.md — the decision, which fallback triggers fired or did not, library version pinned.
  • Integration test: send a malformed frame, get a parse error; send an unknown method, get -32601; send a stub outbound call, observe it lands on stdout.

Acceptance gate. If any of the M1 fallback triggers fire during this PR (outbound boilerplate >10 lines, cancellation interference, _meta friction), this PR is replaced with the hand-rolled framer alternative. Decision is binary and recorded in the ADR before merge.

PR #6 — ACP minimal protocol

Goal. Four inbound methods + one outbound notification, end-to-end through a real Session.

Scope.

  • arnes-acp/src/methods/{initialize, session_new, session_prompt, session_cancel}.rs.
  • arnes-acp/src/frontend.rs — AcpFrontend implements Frontend; translates SessionEvent::AgentMessageDelta to session/update agent_message_chunk notifications.
  • arnes-acp/src/host.rs — AcpHost shell (records client capabilities at initialize; all Host methods Unsupported at M1 since no tool calls into them).
  • arnes-acp/src/main.rs — produces the arnes-acp binary.
  • arnes-acp/tests/golden/m1_basic.jsonl — recorded request/response transcript driven by the scripted LLM from PR #4.

Acceptance. The golden test passes: piping the recorded JSON-RPC frames at arnes-acp produces the expected outbound session/update sequence. Manual smoke: editor can connect, send a prompt, see streamed reply.

PR #7 — Wire Gemini provider + real usage

Goal. A real LLM call produces a real reply, real token counts, and a real cost.

Scope.

  • Enable agent-rig's gemini feature.
  • Construct GeminiModel in both binaries from GEMINI_API_KEY env (or future provider-agnostic config).
  • Verify usage extraction from agent-rig's stream produces non-zero token counts that match the provider's reported figures.
  • Smoke tests gated on GEMINI_API_KEY env (the #[ignore] pattern); CI runs them only in a job with the secret available.

Acceptance. GEMINI_API_KEY=... cargo test -- --ignored passes locally. cumulative_usage() after a real turn shows non-zero tokens and a non-None cost.

PR #8 — Minimal TUI

Goal. arnes binary drops you into a ratatui session that streams a Gemini reply.

Scope.

  • arnes-tui/src/main.rs — clap CLI (CommonOpts flatten), spawns the three tokio tasks.
  • arnes-tui/src/tasks/{input, agent, render}.rs.
  • arnes-tui/src/ui/{layout, input_box, transcript}.rs.
  • arnes-tui/src/frontend.rs — TuiFrontend impl; sends events into the UI command channel.
  • Crossterm raw mode setup; restore on drop (so a panic doesn't wedge the user's terminal).

Acceptance. cargo run -p arnes-tui (with API key) gives a usable chat. Ctrl-C exits cleanly and restores the terminal. Esc cancels a turn in progress. The terminal is never left in raw mode on any panic path (tested manually via panic!() inserted in an agent task).

PR #9 — M1 end-state: smoke tests + docs

Goal. Tie everything off. M1 is mergeable to main as "done."

Scope.

  • Top-level README explains both binaries with five-line examples.
  • arnes-core, arnes-tui, arnes-acp each get a small README with a usage example.
  • A "Hello, arnes" walkthrough doc (docs/getting-started.md): install, set API key, run arnes, send first prompt.
  • CI smoke job: build both binaries on Linux/macOS/Windows; run cargo test --workspace (without API key); verify cargo install --path crates/arnes-tui and crates/arnes-acp both succeed.

Acceptance. README example commands execute. cargo install works on all three OSes. Fresh-clone time from git clone to working arnes prompt is under 5 minutes (modulo Rust toolchain install).

What is deliberately not in M1's PRs

  • Tool calling end-to-end. Lands in M2's first PR. arnes-core::tools::register_defaults() doesn't exist yet; the registry from PR #2 is empty at session start.
  • Real permission flow. The trait surface is in place from PR #2; the modal, session/request_permission outbound call, and matches_scope logic are M3.
  • Persistence. No JSONL write/read in M1. Sessions are ephemeral.
  • Multi-provider support. Gemini only at M1. Adding Anthropic/OpenAI is the parallel "Additional providers" workstream.
