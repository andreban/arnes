feat/frontend-trait

The Frontend trait + the SessionEvent and EventKind types it consumes. Defines what the Session emits and what every adapter (TuiFrontend, AcpFrontend, …) has to implement.

Goal

Ship the Frontend trait (async, dyn-compatible via async-trait), the SessionEvent envelope, the EventKind variant set for M1, and the M3 permission stubs (so the trait can include request_permission without M3 being landed).

Files touched

  • new: crates/arnes-core/src/frontend.rs
  • modify: crates/arnes-core/src/lib.rs
  • modify: root + arnes-core Cargo.toml — add async-trait.

Discussion

1. async-trait recap. Per phase cross-cutting decision 1: use async-trait for dyn-compatibility, applied consistently across Frontend / Host / Tool. Settled; mentioning for completeness.

2. agent-rig's event model anchors the streaming shape. EventKind is what Session translates agent-rig's AgentEvent stream into; its shape should be informed by what agent-rig actually emits, not picked in isolation. Reading src/runner/events.rs: 

pub enum AgentEvent {
    ToolCallStarted  { name: String, args: serde_json::Value },
    ToolCallFinished { name: String, result: ToolCallResult },
    ThinkingDelta(String),
    TextDelta(String),
    Usage(TokenUsage),     // per model call (N per turn if tools fire N times)
    Cancelled,             // terminal; best-effort on cancellation
    Error(crate::error::Error),
}

pub struct RunEvent {
    pub run_id: usize,             // unique per run (root or sub-agent)
    pub parent: Option<usize>,     // None for root; Some(parent_run_id) for sub
    pub agent_event: AgentEvent,
}

Three resolutions fall out:

  • Typed deltas, not block-aware envelopes. agent-rig already chose typed deltas (TextDelta / ThinkingDelta) over Anthropic-style ContentBlockStart/Delta/End. arnes mirrors. Re-bracketing into our own indexed envelope would be overhead for zero benefit.
  • Thinking is first-class in agent-rig. Deferring ThinkingDelta in arnes' EventKind would mean dropping events the moment we wire any thinking-capable provider (Gemini 2.5 in phase 7). The variant lands at M1.
  • Tool calls bracket as Started + Finished, no Update. agent-rig hands us full args at start time; partial-args buffering is its concern. arnes' tool events match agent-rig's variant names when they land (M2, not this PR).

Two things agent-rig does not provide that Session has to inject:

  • TurnStart / TurnEnd boundaries. agent-rig's stream represents one turn (one runner.run() call); stream completion is turn completion, with no explicit boundary event. Session emits TurnStart before consuming the stream and TurnEnd when it ends. (Per-call AgentEvent::Usage(TokenUsage) events arrive mid-stream and are buffered into the turn's TurnUsage; phase 4's session-prompt PR is where that fork lives.)
  • StopReason. agent-rig emits a terminal AgentEvent::Cancelled when a run is cancelled (via token fire or stream-drop); Session maps that directly to Cancelled, and clean stream completion stays at EndTurn. MaxTokens would need an agent-rig upstream contribution and lands when that's possible — not M1.

3. EventKind variant set at M1.

  • TurnStart — injected by Session at run start.
  • TextDelta { text: String } — from agent-rig's TextDelta. (Named to match agent-rig directly so translation is 1:1 with no aliasing.)
  • ThinkingDelta { text: String } — from agent-rig's ThinkingDelta.
  • TurnEnd { stop_reason: StopReason } — injected by Session at stream completion. Phase 3 adds a usage field; that's a struct-variant change requiring a sweep of consumers, which is what we want.
  • Error { message: String } — wraps agent-rig's terminal Error event. Stringly-typed at M1; richer error structure can come later.

Variants not in M1 (added in the PR that first needs them; the compiler will surface every match site to update in the same PR):

  • ToolCallStarted / ToolCallFinished — M2, with the first tool. Re-exporting agent-rig's ToolCallResult vs defining our own equivalent is a decision deferred to that PR.
  • SubAgentStart / SubAgentEnd — post-V1.

4. StopReason variant set at M1.

  • EndTurn — agent-rig stream completed cleanly.
  • Cancelled — the session's cancellation token fired before the stream finished.

Notable deferrals:

  • MaxTokens — would require agent-rig to surface it (the stream currently just ends). When agent-rig gains the capability we add the variant.
  • ToolUse — "stopped because the model is requesting a tool." Doesn't fit agent-rig's M1 event vocabulary, where tool calls are mid-stream events, not stop conditions. Reconsider with M2.
  • Refusal, RateLimit, ProviderError — the last two probably belong in EventKind::Error rather than StopReason. Defer.

5. SessionEvent envelope. { agent_id, depth, kind }. agent-rig's RunEvent envelope (run_id + parent) is the source: root run (parent.is_none()) maps to AgentId::Root; sub-agent run maps to AgentId::SubAgent(Uuid) via a session-local run_id → Uuid table. The depth field is a separate hint for renderers (always 0 at V1).

6. FrontendCapabilities: struct or bitflags? At M1 the struct is empty. Struct-with-bool-fields chosen over bitflags because reads at the call site as expected, serializable, extensible without breaking, and the gain from bitflags is minimal at our scale. Empty struct now; bool fields added per capability when there's a real caller branching on it.

7. Permission stubs. Frontend::request_permission takes a PermissionRequest and returns a Permission. At M1 nothing invokes it (no sensitive tools), but the trait method's signature has to exist now — adding it later would force every Frontend impl to update its signature.

  • PermissionRequest: unit struct. Fleshed out when the permission system lands.
  • Permission: enum { AllowOnce, Deny }. The persistence-aware AllowAlways { scope, persistence } variant arrives with the permission system, along with the Scope / Persistence / Principal types. Nothing in M1 constructs AllowAlways, and shipping empty stub types just to reserve names is the anticipation pattern we've been avoiding.

// Copyright 2026 Andre Cipriani Bandarra

//! Frontend trait and the event vocabulary it consumes.

use async_trait::async_trait;

use crate::AgentId;

/// Implemented by every UI adapter.
#[async_trait]
pub trait Frontend: Send + Sync {
    async fn on_event(&self, event: SessionEvent);
    async fn request_permission(&self, req: PermissionRequest) -> Permission;
    fn capabilities(&self) -> FrontendCapabilities {
        FrontendCapabilities
    }
}

/// One event from the session loop.
#[derive(Clone, Debug)]
pub struct SessionEvent {
    pub agent_id: AgentId,
    pub depth: u8,
    pub kind: EventKind,
}

#[derive(Clone, Debug)]
pub enum EventKind {
    TurnStart,
    TextDelta { text: String },
    /// Model reasoning, distinct from response text.
    ThinkingDelta { text: String },
    TurnEnd { stop_reason: StopReason },
    Error { message: String },
}

#[derive(Clone, Debug)]
pub enum StopReason {
    EndTurn,
    Cancelled,
}

/// Permission-prompt payload. Filled in when the permission system lands.
#[derive(Clone, Debug, Default)]
pub struct PermissionRequest;

/// Frontend's verdict on a permission request.
#[derive(Clone, Debug)]
pub enum Permission {
    AllowOnce,
    Deny,
}

/// What the frontend supports. Bool fields added per capability when
/// there's a real caller branching on it.
#[derive(Clone, Debug, Default)]
pub struct FrontendCapabilities;
