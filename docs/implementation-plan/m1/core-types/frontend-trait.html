feat/frontend-trait

The Frontend trait + the SessionEvent and EventKind types it consumes. Defines what the Session emits and what every adapter (TuiFrontend, AcpFrontend, …) has to implement.

Goal

Ship the Frontend trait (async, dyn-compatible via async-trait), the SessionEvent envelope, the EventKind variant set for M1, and the M3 permission stubs (so the trait can include request_permission without M3 being landed).

Files touched

  • new: crates/arnes-core/src/frontend.rs
  • modify: crates/arnes-core/src/lib.rs
  • modify: root + arnes-core Cargo.toml — add async-trait.

Discussion

1. async-trait recap. Per phase cross-cutting decision 1: use async-trait for dyn-compatibility. Frontend is generic in Session<F: Frontend, H: Host> (so could in principle skip dyn), but applying async-trait consistently across Frontend / Host / Tool avoids the mental tax of "which traits use which async style." Settled; mentioning for completeness.

2. EventKind variant set at M1. The minimal sequence per turn looks like: 

TurnStart
→ AgentMessageDelta (zero or more)
→ TurnEnd { stop_reason }
(or Error { message } if something fails before TurnEnd)

Variants for M1:

  • TurnStart — signals "the agent is now producing output for this user turn." Frontend uses it to clear "is the assistant typing" indicators, etc.
  • AgentMessageDelta { text: String } — one chunk of streamed assistant text. Concatenated by frontends.
  • TurnEnd { stop_reason: StopReason } — the turn finished. M1 doesn't yet carry usage; the Usage type doesn't exist until phase 3, and the next phase's first PR (feat/turnend-usage-wiring) adds the field. #[non_exhaustive] on EventKind makes that addition non-breaking.
  • Error { message: String } — terminal failure. M1 keeps it stringly-typed; phase 3+ may refine to a richer error variant.

Variants not in M1:

  • ThinkingDelta { text } — should we stream thinking blocks as separate events? Discussion: probably yes, since frontends will want to differentiate styling. But this is interrogable from AgentMessageDelta if we embed type info, and adding the variant later is non-breaking. Defer — revisit when the Gemini-thinking integration in phase 7 actually produces them and we see how agent-rig surfaces the distinction.
  • ToolCallStart / ToolCallUpdate / ToolCallEnd — M2.
  • SubAgentStart / SubAgentEnd — post-V1.

3. StopReason variant set. agent-rig presumably surfaces these from each provider's wire-level stop reason. Coverage in M1 should be at least:

  • EndTurn — model finished cleanly.
  • MaxTokens — hit response token limit.
  • Cancelled — we cancelled the turn via Session::cancel.

Plausibly also:

  • ToolUse — stopped because the model requested a tool. M1 has no tools so this never happens; M2 adds it. Defer.
  • Refusal — model declined (safety, policy). Defer until we have a caller that cares.
  • RateLimit / ProviderError — these probably belong in EventKind::Error instead.

Decision: M1 ships EndTurn, MaxTokens, Cancelled. Enum is #[non_exhaustive] so M2's ToolUse variant is additive.

4. FrontendCapabilities: struct or bitflags? At M1 the struct is empty. The shape decision matters for the future:

  • Struct with bool fields (chosen): { supports_markdown: bool, supports_images: bool, ... }. Reads at the call site as expected; serializable; extensible without breaking.
  • Bitflags: compact, but you write caps.contains(Caps::MARKDOWN); serde story is less natural; gain is minimal at our scale.

Empty struct now; bool fields added per capability when there's a real caller branching on it.

5. The M3 stubs. Frontend::request_permission takes a PermissionRequest and returns a Permission. M3 fleshes out both types (scopes, principals, persistence policy — see core.html future-compat table). At M1 these are empty stubs:

  • PermissionRequest: unit struct. The trait method exists; no in-tree caller invokes it yet (no tools to permission).
  • Permission: enum AllowOnce | AllowAlways { scope, persistence } | Deny. M1 callers (if any) construct AllowOnce or Deny.
  • Scope, Persistence, Principal: unit-struct stubs.

M2 / M3 flesh out the bodies. The trait surface needs the types present now so it doesn't acquire request_permission as a breaking method addition.

6. SessionEvent envelope. { agent_id, depth, kind }. The depth field exists for sub-agent nesting (always 0 at V1); it's a separate field rather than encoded in agent_id so a renderer can use it for indentation without having to compute parentage. See future-compat § SessionEvent.

//! The `Frontend` trait: what every UI adapter implements to consume
//! session events and answer permission requests.

use async_trait::async_trait;

use crate::AgentId;

/// Implemented by every UI adapter (TUI, ACP, HTTP, GUI, ...).
///
/// Object-safe via `async-trait`; can be held as `Arc<dyn Frontend>`
/// or used generically through `Session<F: Frontend, H: Host>`.
#[async_trait]
pub trait Frontend: Send + Sync {
    /// Receive one event from the session. Implementations should not
    /// block on user input here — that belongs in
    /// `request_permission`.
    async fn on_event(&self, event: SessionEvent);

    /// Ask the user to allow / deny a sensitive operation. At M1 no
    /// caller invokes this (no sensitive tools exist yet); M2 / M3 wire
    /// it up.
    async fn request_permission(&self, req: PermissionRequest) -> Permission;

    /// What this frontend supports. Default: nothing — the empty
    /// struct is a forward-compatible placeholder.
    fn capabilities(&self) -> FrontendCapabilities {
        FrontendCapabilities::default()
    }
}

/// One event from the session loop.
#[derive(Clone, Debug)]
pub struct SessionEvent {
    /// Which agent produced this event. V1 is always
    /// [`AgentId::Root`].
    pub agent_id: AgentId,
    /// Nesting depth for sub-agent rendering. V1 is always 0.
    pub depth: u8,
    /// What happened.
    pub kind: EventKind,
}

/// Discriminator for event payloads. New variants are added by sweeping
/// in-tree match sites; `#[non_exhaustive]` keeps that non-breaking.
#[derive(Clone, Debug)]
#[non_exhaustive]
pub enum EventKind {
    /// Agent is about to start producing output for the current turn.
    TurnStart,

    /// One chunk of streamed assistant text. Multiple per turn.
    AgentMessageDelta { text: String },

    /// Turn finished. Phase 3's `feat/turnend-usage-wiring` adds a
    /// `usage: Usage` field; `#[non_exhaustive]` makes that addition
    /// non-breaking for consumers.
    TurnEnd { stop_reason: StopReason },

    /// Terminal failure (provider error, transport drop, …).
    Error { message: String },

    // M2 adds: ToolCallStart, ToolCallUpdate, ToolCallEnd.
    // Post-V1 adds: SubAgentStart, SubAgentEnd, ThinkingDelta (maybe).
}

#[derive(Clone, Debug)]
#[non_exhaustive]
pub enum StopReason {
    /// Model finished cleanly.
    EndTurn,
    /// Hit response token limit.
    MaxTokens,
    /// Caller invoked [`crate::Session::cancel`].
    Cancelled,
    // M2 adds: ToolUse.
}

// --- M3 permission stubs ---

/// Permission-prompt payload. Empty stub at M1; M3 adds scope/summary
/// fields and wires the modal.
#[derive(Clone, Debug, Default)]
pub struct PermissionRequest;

/// Frontend's verdict on a permission request.
#[derive(Clone, Debug)]
pub enum Permission {
    /// Allow this one invocation only.
    AllowOnce,
    /// Allow within a scope, persisted per the policy.
    AllowAlways {
        scope: Scope,
        persistence: Persistence,
    },
    /// Deny this invocation.
    Deny,
}

#[derive(Clone, Debug, Default)] pub struct Scope;        // M3 fleshes out
#[derive(Clone, Debug, Default)] pub struct Persistence;  // M3 fleshes out
#[derive(Clone, Debug, Default)] pub struct Principal;    // M3 fleshes out

/// What the frontend supports. Empty at M1; bool fields added per
/// capability when there's a real caller branching on it.
#[derive(Clone, Debug, Default)]
pub struct FrontendCapabilities;

Tests

None for this PR. The trait has no behavior to test; SessionEvent and EventKind are pure data. Test coverage comes in:

  • Phase 4's feat/session-roundtrip-test — asserts the event sequence (TurnStart, N×AgentMessageDelta, TurnEnd) for a scripted-LLM round-trip.
  • Phase 4's feat/recording-frontend — the test helper itself exercises every variant we construct.
