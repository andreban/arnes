feat/host-trait

The Host trait — OS resources (filesystem, terminal) that tools talk to via abstraction. M1 ships the trait, the associated data types, a LocalHost impl that returns Unsupported for every method, and one #[tokio::test] per method asserting that Unsupported contract.

Goal

Define the OS-resource trait that every adapter ships an implementation of, with all methods defaulting to Unsupported so M1 binaries can construct a session without yet having any working host. Real impls land in M3 alongside the first sensitive tools.

Files touched

  • new: crates/arnes-core/src/host.rs
  • new: crates/arnes-core/tests/local_host_unsupported.rs
  • modify: crates/arnes-core/src/lib.rs
  • modify: crates/arnes-core/Cargo.toml — add [dev-dependencies] tokio = { version = "1", features = ["macros", "rt"] } for #[tokio::test].

No [workspace.dependencies] entry for tokio yet — the dev-dep is the first usage and is scoped to this crate's tests. Phase 4 promotes tokio to a workspace dep when Session needs it at runtime.

Discussion

1. The Method set. ACP defines a long menu of host capabilities (fs/read_text_file, fs/write_text_file, fs/list_directory, terminal/create, terminal/snapshot, terminal/kill, terminal/release, env reads, …). At M1 we ship the conservative starting set:

  • read_text_file
  • write_text_file
  • list_directory
  • terminal_create
  • terminal_snapshot
  • terminal_kill
  • terminal_release

No method has a caller yet at M1 (tools land in M2; ACP forwarding in phase 6). The shipped set anticipates what M2's first tools (read, write, edit, bash) will need. Default-Unsupported pattern means adding more methods later (e.g. stat, delete, glob) is a one-line addition that doesn't break existing impls.

Worth flagging: alternative would be a much smaller M1 set (just read_text_file and terminal_create) and add the rest in M2. Either is defensible. Shipping the larger set now keeps the trait shape settled before M2 adds real impls, and the cost is purely doc-comment writing (the default bodies are one-liners).

2. Default-to-Unsupported pattern. Every method has a default body that returns Err(io::ErrorKind::Unsupported). This means:

  • LocalHost can be a unit struct with an empty impl Host for LocalHost {} — no methods to write at M1.
  • Adding a new method to the trait doesn't break any existing impl; it just falls through to Unsupported.
  • The unit tests pin this behavior: if someone "helpfully" overrides a method without thinking it through, the test catches the missing assertion.

3. Why not use std::io::Error with custom ErrorKind? io::ErrorKind::Unsupported is the natural match: it already means "the operation isn't supported in this context." We're not inventing semantics; we're using the stdlib's exact intent.

4. Trait method signatures.

  • read_text_file returns io::Result<String>: text-only; binary reads aren't a use case yet (M2/M3 might add read_bytes).
  • write_text_file takes &str: same logic; binary writes deferred.
  • list_directory returns Vec<DirEntry>: not async-streamed at M1 (directory sizes are bounded for the editor / tool use cases we target).
  • terminal_* work on TerminalHandle values: opaque (just wraps a UUID); the actual process management is the impl's problem.

5. LocalHost being a unit struct. M1 it's literally pub struct LocalHost; impl Host for LocalHost {}. M3 fills in real implementations (tokio::fs wrappers, PTY for terminals). The unit-struct shape stays the same; only the impl grows.

Deps

crates/arnes-core/Cargo.toml, append:

[dev-dependencies]
tokio = { version = "1", features = ["macros", "rt"] }

tokio is a dev-only dep here because we don't run anything on a tokio runtime in arnes-core code yet — we just need #[tokio::test] to drive async assertions. Phase 4 promotes tokio to a normal workspace dep when Session spawns tasks.

Code skeleton

// Copyright 2026 Andre Cipriani Bandarra
// SPDX-License-Identifier: Apache-2.0

//! OS-resource abstraction.
//!
//! Tools never touch `std::fs` / `tokio::process` directly; they route
//! through a `&dyn Host` from their `ToolContext`. Each adapter ships
//! an implementation (`LocalHost` here for in-process; `AcpHost` in
//! `arnes-acp` for editor-mediated I/O).

use std::{io, path::Path, path::PathBuf};

use async_trait::async_trait;
use uuid::Uuid;

/// OS-resource trait. Every method defaults to
/// `io::ErrorKind::Unsupported` so adding methods is non-breaking and
/// minimal impls (like `LocalHost` at M1) need not list every method.
#[async_trait]
pub trait Host: Send + Sync {
    async fn read_text_file(&self, _path: &Path) -> io::Result<String> {
        unsupported()
    }

    async fn write_text_file(&self, _path: &Path, _contents: &str) -> io::Result<()> {
        unsupported()
    }

    async fn list_directory(&self, _path: &Path) -> io::Result<Vec<DirEntry>> {
        unsupported()
    }

    async fn terminal_create(&self, _spec: TerminalSpec) -> io::Result<TerminalHandle> {
        unsupported()
    }

    async fn terminal_snapshot(&self, _handle: &TerminalHandle) -> io::Result<TerminalSnapshot> {
        unsupported()
    }

    async fn terminal_kill(&self, _handle: &TerminalHandle) -> io::Result<()> {
        unsupported()
    }

    async fn terminal_release(&self, _handle: TerminalHandle) -> io::Result<()> {
        unsupported()
    }
}

fn unsupported<T>() -> io::Result<T> {
    Err(io::Error::new(
        io::ErrorKind::Unsupported,
        "not implemented at this milestone",
    ))
}

// --- Data types ---

#[derive(Clone, Debug)]
pub struct DirEntry {
    pub name: String,
    pub is_dir: bool,
}

#[derive(Clone, Debug)]
pub struct TerminalSpec {
    pub command: String,
    pub args: Vec<String>,
    pub cwd: Option<PathBuf>,
}

#[derive(Clone, Debug)]
pub struct TerminalHandle {
    pub id: Uuid,
}

#[derive(Clone, Debug)]
pub struct TerminalSnapshot {
    pub output: String,
    pub exit_code: Option<i32>,
}

// --- The in-process default impl ---

/// In-process host: real `tokio::fs` / PTY implementations land in M3.
/// At M1 it relies on every default body, so every call returns
/// `io::ErrorKind::Unsupported`.
pub struct LocalHost;

#[async_trait]
impl Host for LocalHost {}

Tests

tests/local_host_unsupported.rs — one #[tokio::test] per Host method: 

// Copyright 2026 Andre Cipriani Bandarra
// SPDX-License-Identifier: Apache-2.0

use std::{io, path::PathBuf};

use arnes_core::{Host, LocalHost, TerminalHandle, TerminalSpec};
use uuid::Uuid;

fn handle() -> TerminalHandle {
    TerminalHandle { id: Uuid::now_v7() }
}

fn spec() -> TerminalSpec {
    TerminalSpec { command: "echo".into(), args: vec!["hi".into()], cwd: None }
}

#[tokio::test]
async fn read_text_file_is_unsupported() {
    let err = LocalHost.read_text_file("/tmp/x".as_ref()).await.unwrap_err();
    assert_eq!(err.kind(), io::ErrorKind::Unsupported);
}

#[tokio::test]
async fn write_text_file_is_unsupported() {
    let err = LocalHost.write_text_file("/tmp/x".as_ref(), "hi").await.unwrap_err();
    assert_eq!(err.kind(), io::ErrorKind::Unsupported);
}

#[tokio::test]
async fn list_directory_is_unsupported() {
    let err = LocalHost.list_directory(PathBuf::from("/tmp").as_ref()).await.unwrap_err();
    assert_eq!(err.kind(), io::ErrorKind::Unsupported);
}

#[tokio::test]
async fn terminal_create_is_unsupported() {
    let err = LocalHost.terminal_create(spec()).await.unwrap_err();
    assert_eq!(err.kind(), io::ErrorKind::Unsupported);
}

#[tokio::test]
async fn terminal_snapshot_is_unsupported() {
    let h = handle();
    let err = LocalHost.terminal_snapshot(&h).await.unwrap_err();
    assert_eq!(err.kind(), io::ErrorKind::Unsupported);
}

#[tokio::test]
async fn terminal_kill_is_unsupported() {
    let h = handle();
    let err = LocalHost.terminal_kill(&h).await.unwrap_err();
    assert_eq!(err.kind(), io::ErrorKind::Unsupported);
}

#[tokio::test]
async fn terminal_release_is_unsupported() {
    let err = LocalHost.terminal_release(handle()).await.unwrap_err();
    assert_eq!(err.kind(), io::ErrorKind::Unsupported);
}
