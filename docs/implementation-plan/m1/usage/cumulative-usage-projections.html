feat/cumulative-usage-projections

CumulativeUsage::by_model() and by_agent() — derived flatten-style views over the underlying (AgentId, ModelKey) map. The data the frontend's per-model and per-agent renderings consume.

Goal

Add two projection methods to CumulativeUsage; cover them with a projection-consistency test (sums match across views).

Files touched

  • modify: crates/arnes-core/src/metering/cumulative_usage.rs — append projection methods on CumulativeUsage.

No new deps. No new exports (the methods are on an already-exported type).

Discussion

1. What the projections return. Each is a flatten of the underlying (AgentId, ModelKey) -> ModelUsage map onto a single dimension:

  • by_model(): for each ModelKey, sum every bucket that shares that key (across agents). Useful for "how many tokens did each model produce, regardless of which agent invoked it."
  • by_agent(): for each AgentId, sum every bucket that shares that ID (across models). Useful at V1 only-Root, but mandatory for post-V1 sub-agent attribution.

2. Return type: owned vs borrowed keys. Two options:

  • HashMap<&ModelKey, ModelUsage> (chosen): keys are borrowed from the underlying map; values are owned (constructed by summing). Callers can't outlive the registry, but they don't need to — rendering is synchronous; the projection is computed on demand.
  • HashMap<ModelKey, ModelUsage>: keys cloned. Simpler ownership story; trivial extra cost (the keys are two small Strings). Less idiomatic for a quick view.

The borrowed-key version is the natural fit and matches what core.html's usage spec already commits to. Recheck if callers ever need to outlive the registry — if so, we add a by_model_owned() convenience later.

3. ModelUsage values in the projection carry the model field (and effectively encode the AgentId in by_agent) so a consumer iterating the values doesn't need the key.

4. Projection-consistency invariant. Two sums that must always match (proven by the test):

  • Sum of by_model() values' tokens.total = sum of by_agent() values' tokens.total = sum of every recorded turn's tokens.
  • Sum of by_model() values' turns = sum of by_agent() values' turns = turns_total.

This invariant is what makes the projections trustworthy. The test asserts it on a fixture with at least two distinct (agent, model) pairs to make the projection non-trivial.

5. Why projections rather than just iterators? A consumer could iterate cumulative.values() and bucket themselves. Pros of shipping the projections:

  • The "right" bucketing logic lives in one place (this PR), not duplicated in every frontend / persistence row / ACP usage frame.
  • Discoverability: a developer asking "how do I get per-model totals?" finds by_model() immediately.
  • The consistency invariant is testable centrally rather than per-consumer.

Cost of shipping them: ~20 lines of code per projection. Worth it.

Code skeleton

// Appended to crates/arnes-core/src/metering/cumulative_usage.rs:

impl CumulativeUsage {
    /// Flatten across agents: total per `ModelKey`.
    pub fn by_model(&self) -> HashMap<&ModelKey, ModelUsage> {
        let mut out: HashMap<&ModelKey, ModelUsage> = HashMap::new();
        for ((_, model), bucket) in &self.by_agent_and_model {
            let entry = out.entry(model).or_insert_with(|| ModelUsage {
                model: model.clone(),
                tokens: TokenCounts::default(),
                turns: 0,
            });
            merge_into(entry, bucket);
        }
        out
    }

    /// Flatten across models: total per `AgentId`. The `model` field on
    /// the returned `ModelUsage` is undefined (kept for shape; callers
    /// inspecting per-agent rows should treat it as opaque).
    pub fn by_agent(&self) -> HashMap<&AgentId, ModelUsage> {
        let mut out: HashMap<&AgentId, ModelUsage> = HashMap::new();
        for ((agent, model), bucket) in &self.by_agent_and_model {
            let entry = out.entry(agent).or_insert_with(|| ModelUsage {
                model: model.clone(),
                tokens: TokenCounts::default(),
                turns: 0,
            });
            merge_into(entry, bucket);
        }
        out
    }
}

fn merge_into(into: &mut ModelUsage, from: &ModelUsage) {
    into.tokens += from.tokens;
    into.turns  += from.turns;
}

Open call: the by_agent() projection returns a ModelUsage whose model field is whichever model happened to be picked from or_insert_with — semantically meaningless when summing across models. A cleaner shape would be a separate AgentUsage type with no model field, but that's a duplication for one field. The doc comment notes "treat as opaque." Revisit if callers find this awkward.

Tests

  • Empty: both projections return empty maps for an empty CumulativeUsage.
  • Single bucket: one recorded TurnUsage shows up as one entry in both projections, with totals matching the original.
  • Two models, one agent: two TurnUsages with same AgentId but different ModelKeys — by_model returns 2 entries; by_agent returns 1 entry with summed totals.
  • One model, two agents: mirror of above (only meaningful post-V1, but exercises the bucketing code).
  • Projection consistency: with a fixture of 3+ distinct (agent, model) buckets, assert sums match: sum of by_model() values' tokens equals sum of by_agent() values' tokens equals the sum of all recorded turn tokens.
