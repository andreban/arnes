M1 · Phase 3 · PR 1 of 4

feat/usage-record

TurnUsage (the per-turn record) and ModelUsage (the aggregated-row shape that CumulativeUsage stores per bucket in PR #2). Also lands TokenCounts — the one-field token count that both records hold.

Goal

Define the per-turn usage record and the aggregated row shape it folds into.

Files touched

  • new: crates/arnes-core/src/metering/token_counts.rs, turn_usage.rs, model_usage.rs.
  • modify: crates/arnes-core/src/metering/mod.rs + crates/arnes-core/src/lib.rs — module + re-exports.

No new deps.

Discussion

1. TokenCounts shape. One field (total: u64) with Add / AddAssign for aggregation. An earlier prototype carried five per-kind fields (input, output, cache_read, cache_write, thinking) because the cost calculator needed per-kind rates; with cost gone there is no consumer for the breakdown. Keeping the struct (rather than a bare u64 on TurnUsage) leaves a place to grow back per-kind fields without renaming every site that reads usage.tokens.

2. TurnUsage carries agent_id and ModelKey. Already established in core.html's future-compat table: every TurnUsage is tagged with which agent produced it and which model it was billed to. Phase 4's Session sets these at the boundary; CumulativeUsage (PR #2) uses the (agent_id, model) pair as its hash-map key.

3. ModelUsage shape. One bucket's aggregated state — what CumulativeUsage stores per (AgentId, ModelKey) key:

  • tokens: TokenCounts — sum across all turns in this bucket.
  • turns: u32 — how many turns landed in this bucket.

The model: ModelKey field on ModelUsage duplicates half of the map key, which makes flattened views (PR #3) cleaner: a by_model() result is a list of ModelUsage values that already know which model they're about.

Code skeleton

// crates/arnes-core/src/metering/token_counts.rs

use std::ops::{Add, AddAssign};

#[derive(Clone, Copy, Debug, Default, Eq, PartialEq)]
pub struct TokenCounts {
    pub total: u64,
}

impl Add for TokenCounts { /* field-wise */ }
impl AddAssign for TokenCounts { /* field-wise */ }

// crates/arnes-core/src/metering/turn_usage.rs

use crate::{AgentId, ModelKey, TokenCounts};

#[derive(Clone, Debug)]
pub struct TurnUsage {
    pub agent_id: AgentId,
    pub model:    ModelKey,
    pub tokens:   TokenCounts,
}

// crates/arnes-core/src/metering/model_usage.rs

use crate::{ModelKey, TokenCounts};

#[derive(Clone, Debug)]
pub struct ModelUsage {
    pub model:  ModelKey,
    pub tokens: TokenCounts,
    pub turns:  u32,
}

lib.rs additions

pub use metering::{ModelUsage, TokenCounts, TurnUsage};

Tests

  • Round-trip construction: build a TurnUsage with non-zero tokens; pattern-match back.
  • TokenCounts::AddAssign: two values sum field-wise; default is zero.

Aggregation behaviour (constructing a ModelUsage from a series of TurnUsages) is tested in PR #2 where the record() method lands.
