M1 · Phase 3

Usage

Token-count types and per-(agent, model) aggregation. A frontend can display "how many tokens did this session burn" broken down by model or by agent. One total per turn for V1; per-kind breakdowns (input / output / cache / thinking) can grow back when there is a real consumer for them.

Cost tracking removed. An earlier revision of this phase shipped a Cost / Micros / ModelPricing / PricingRegistry stack with a three-state Priced / Free / Unknown pricing model and a JSON loader for ~/.arnes/pricing.json. We walked it back: the harness displays token counts only and leaves cost conversion to whoever wants to compute it from those counts. The user-facing reasons:
  • Bundled defaults would have committed us to keeping rates current; pushing the file to users shifts the maintenance to whoever cares enough to populate it — at which point they can just compute cost themselves.
  • Per-token-kind breakdown (input / output / cache / thinking) is what cost calculation needed. Without cost, one total per turn is enough for V1 displays.
  • "Unknown is never silently zero" only matters once cost numbers are on the screen. With tokens only, there is no zero to confuse anyone.

Order matters: PRs 1–2 build the type stack bottom-up (TokenCounts → TurnUsage / ModelUsage → CumulativeUsage). PR #3 (by_model / by_agent) needs CumulativeUsage, so it lands after #2. PR #4 (wire into EventKind::TurnEnd) needs TurnUsage (#1) and is independent of the aggregation work.

Cross-cutting decisions (settled)

1. TokenCounts carries one total field for V1. Earlier prototypes carried five fields (input, output, cache_read, cache_write, thinking) because the cost calculator needed per-kind rates. With cost calculation gone the displays we actually want to ship at M1–M3 only show one number ("12.3k tokens"). Keeping the struct (rather than a bare u64 on TurnUsage) leaves a place to grow back per-kind fields without renaming every site that reads usage.tokens.

2. Per-(agent, model) bucketing stays. CumulativeUsage still indexes by (AgentId, ModelKey). V1 only ever populates (AgentId::Root, <current model>), but the keyed map is the source of truth so post-V1 sub-agents and mid-session model switches are additive, not breaking.

Discussion sections in each PR doc

  • usage-record: shape of TurnUsage (agent_id + ModelKey + tokens); ModelUsage as the aggregated row.
  • cumulative-usage: indexing by (AgentId, ModelKey); record() semantics.
  • cumulative-usage-projections: borrowed vs owned view returns; projection consistency invariant; whether to expose iterators instead.
  • turnend-usage-wiring: one-field addition; consumer sweep.

Test strategy for the phase

  • Per-(agent, model) bucketing (PR #2): two synthetic TurnUsage values with different ModelKeys produce two entries in CumulativeUsage.
  • Cumulative sums are consistent (PRs #2 + #3): the sum of by_model() token totals equals the sum of by_agent() token totals equals the sum of every recorded turn's tokens.
