Milestone 1 · Foundation

agent-rig + minimal TUI + minimal ACP

Stand up the Cargo workspace; define the two key traits; bring up two minimal frontends in parallel. By the end you have a working LLM round-trip in both a ratatui input/output pair and a JSON-RPC server on stdio — same harness, two faces.

Why this milestone exists first

The whole architecture rests on the Frontend and Host traits. Standing them up while they only need to support streaming text — not tools, not permissions, not files — is the cheapest possible validation of the design. Building two consumers of the same harness immediately means we'll notice if a trait feels TUI-shaped before we are deep into the implementation.

JSON-RPC library: start with jsonrpsee, fall back if needed

ACP requires bidirectional dispatch on a single channel: arnes must serve inbound requests from the editor and send server-initiated requests back to it (fs/*, terminal/*) over the same stdio. Many Rust JSON-RPC crates handle only one direction comfortably.

The decision: we start with jsonrpsee. If its server-initiated dispatch turns out to be painful enough during M1 (or later milestones) we fall back to a hand-rolled framer + dispatcher built on tokio_util::codec::LinesCodec. Roll-your-own is the fallback, not the default — the bug list and test matrix are worth avoiding if jsonrpsee carries its weight.

CandidateStatusNotes
jsonrpsee Default choice Bidirectional supported; well-maintained; rich middleware. Server-initiated request API is verbose but workable.
Hand-rolled (LinesCodec + dispatcher) Documented fallback ~350 lines total. Switch to this if jsonrpsee fights us on outbound calls, cancellation, or _meta propagation.
tower-lsp internals Considered, rejected Bidirectional baked in but tied to LSP types; depopulating is significant work for no clear win over jsonrpsee.

Concrete triggers for invoking the fallback during M1 implementation (in arnes-acp/src/transport/):

  • AcpHost outbound-call helpers (fs/read_text_file, terminal/create, …) need more than ~10 lines of boilerplate per method.
  • jsonrpsee's request-correlation machinery interferes with the per-session CancellationToken wiring.
  • Adding ACP-specific bits (the _meta field we'll need for compaction at M7) requires fighting the library's serialization layer.

If none of those happen, stay on jsonrpsee. Record the trade-off and any triggers that almost fired in a one-page ADR (docs/adr/0001-jsonrpc-library.md) for future maintainers.

    │   │   ├── host.rs           # Host trait + LocalHost impl (next to trait)
    │   │   ├── session.rs        # Session<F, E>, run loop wrapper
    │   │   ├── message.rs        # Message, ContentBlock (text + tool stubs)
    │   │   └── error.rs
    │   ├── tests/
    │   │   └── session_roundtrip.rs
    │   └── Cargo.toml
    ├── arnes-tui/                # ratatui app; binary `arnes`
    └── arnes-acp/                # JSON-RPC server on stdio; binary `arnes-acp`
        └── src/host.rs            # AcpHost: outbound JSON-RPC proxy

Two binaries, one per adapter crate. The TUI binary is named arnes (the daily driver); the ACP server is arnes-acp, spawned by editors. arnes-serve (HTTP) lands at M8; arnes-gui at M9. No central CLI router.

Note where the two Host impls live: LocalHost sits next to the trait in arnes-core::host (it is ~200 lines of tokio wrappers; a dedicated crate buys nothing); AcpHost sits inside arnes-acp because it is tightly coupled to that adapter's outbound JSON-RPC machinery.

The arnes-core::tools module does not exist yet — it shows up at M2 with the first real tool. LocalHost (in arnes-core::host) and AcpHost (in arnes-acp::host) exist but expose only the Host impl shell, since no tool yet calls into them.

Traits to define

These are the signatures the rest of the project commits to. Get them right enough to ship M1; expect minor refinements during M2–M3 as real tools and real permission flows materialize.

pub trait Frontend: Send + Sync {
    async fn on_event(&self, event: SessionEvent);
    async fn request_permission(&self, req: PermissionRequest) -> Permission;
    fn capabilities(&self) -> FrontendCapabilities { Default::default() }
}

pub enum AgentId {
    Root,
    SubAgent(Uuid),         // never minted at V1; reserved for post-V1 sub-agents
}

}

    // M2 adds ToolCallStart/Update/End. Future SubAgentStart/SubAgentEnd

}

pub trait Host: Send + Sync {
    // M1: declare all methods but only require <none> at this milestone;
    // every default impl returns ErrorKind::Unsupported.
    async fn read_text_file(&self, _: &Path) -> io::Result<String>        { unsupported() }

    Err(io::Error::new(io::ErrorKind::Unsupported, "not implemented in this milestone"))
}
// arnes-core/src/session.rs

pub struct Session<F: Frontend, H: Host> {
    pub agent_id: AgentId,        // V1: always Root
    parent:       Option<Weak<Session<F, H>>>,   // V1: always None
    frontend:     Arc<F>,
    host:         Arc<H>,
    runner:       agent_rig::runner::AgentRunner,
    history:      Vec<agent_rig::model::Message>,
    cancel:       CancellationToken,
    model:        ModelKey,       // current backend+model for usage attribution
}

impl<F, H> Session<F, H> where F: Frontend, H: Host {
    pub fn new(frontend: Arc<F>, host: Arc<H>, runner: AgentRunner, model: ModelKey) -> Self {
        // V1: agent_id = AgentId::Root, parent = None.
    }

    // Post-V1 sub-agents are registered as agent-rig AgentTools in
    // the ToolRegistry; no Session::spawn_subagent method exists.

    pub async fn prompt(&mut self, text: String) -> Result<()> {
        self.history.push(Message::user(text));
        let mut stream = self.runner.run(&self.agent_def(), self.history.clone());
        self.emit(EventKind::TurnStart).await;
        while let Some(ev) = stream.next().await {
            // M1 emits only text and thinking deltas; tool calls land in M2.
            match ev.agent_event {
                AgentEvent::TextDelta(text)     => self.emit(EventKind::TextDelta     { text }).await,
                AgentEvent::ThinkingDelta(text) => self.emit(EventKind::ThinkingDelta { text }).await,
                _ => {}
            }
        }
        self.emit(EventKind::TurnEnd { /* stop_reason, usage with agent_id + model */ }).await;
        Ok(())
    }

    pub fn cancel(&self) { self.cancel.cancel() }
}

Usage subsystem stub

Define the data shapes and the pricing-registry loader in arnes-core::usage. Token tracking starts working at M1; cost calculation works for the few models we seed; everything else is ModelCostInfo::Unknown and surfaces as such.

  • Types: ModelKey, Usage (carries agent_id + model), Cost, Micros, ModelCostInfo, ModelPricing, ModelUsage, CumulativeUsage (indexed by (AgentId, ModelKey)). See core.html § usage for the full shape.
  • Bundled pricing TOML at arnes-core/data/pricing.toml, seeded for the Gemini models we wire up at M1 and a wildcard Free entry for Ollama.
  • Session reads token counts off agent-rig's stream at turn end, builds Usage with its own agent_id + the active ModelKey, computes cost via the registry, emits EventKind::TurnEnd { stop_reason, usage }.
  • Session::cumulative_usage() -> CumulativeUsage accessor for frontends. V1 only ever has one entry under (AgentId::Root, model), but the per-(agent, model) map is the source of truth so post-V1 sub-agents and mid-session model switches are additive, not breaking.
  • Frontends at M1 don't have to render usage yet (M3 wires the TUI status line), but the data — including the per-model breakdown view via cumulative_usage().by_model() — is available.

TUI scope at M1

Two regions: scrolling transcript on top, single-line input on bottom. No status row, no slash commands, no tool cards yet.
  • ratatui + crossterm. Three tokio tasks: input, agent, render (per adapter-tui.html).
  • Plain text rendering — no markdown, no syntax highlighting.
  • Enter submits, Ctrl-C exits, Esc cancels the current turn if one is running.
  • No history scrollback (just whatever the terminal naturally shows).
  • TuiFrontend auto-allows all permission requests (no sensitive tools exist yet).

ACP scope at M1

Method / notificationBehaviour at M1
initialize Negotiate protocol version; advertise minimal agent capabilities (no fs, no terminal, no MCP); record client capabilities (advisory only at M1).
session/new Construct a Session<AcpFrontend, AcpHost>; mint a UUID v7; return it. cwd from client may be ignored at M1.
session/prompt Push the user message, call session.prompt(), return final stop_reason.
session/cancel Notification; calls session.cancel().
session/update Outbound notification. Only agent_message_chunk variant emitted at M1.

Everything else (session/load, set_mode, request_permission, fs/*, terminal/*) responds with JSON-RPC error -32601 Method not found if asked. Capability flags signal upfront that these aren't supported.

CLI surface

$ arnes                              # launch TUI
$ arnes --model gemini-2.5-flash     # TUI with model override
$ arnes-acp                          # speak ACP on stdio (editor-spawned)

Each binary parses its own flags via clap. Common options (--model, --cwd, …) live in a shared CommonOpts struct in arnes-core::cli that both binaries flatten into their own options via #[command(flatten)].

Work plan

For the broken-down execution plan — phase by phase, PR by PR, with the architectural choices surfaced for discussion in each — see the M1 work plan.

Testing checklist

  • arnes-core unit: Session::prompt with mock Frontend + mock Host + agent-rig in "echo" mode. Assert event sequence: TurnStart, N×AgentMessageDelta, TurnEnd.
  • arnes-acp golden: a JSON-lines transcript file (tests/golden/m1_basic.jsonl) with inbound requests and expected outbound notifications. Replay; diff.
  • arnes-tui smoke: manual. Type "hello"; reply streams in.
  • Lint: cargo clippy --workspace --all-targets -- -D warnings.

Risks specific to M1

  • jsonrpsee turns out to be the wrong choice. Mitigation: the documented fallback (hand-rolled framer) is ~350 lines and the triggers are explicit, so the switch is a 2–3 day detour, not a redesign. The arnes-acp::transport module isolates the framing so the rest of the adapter is unaffected.
  • agent-rig public API edges. If something we need isn't public, contribute a PR upstream rather than forking. Plan for one round-trip with upstream during M1.
  • Trait premature lock-in. The traits will need at least one revision when M2/M3 land permissions and tool calls. Embrace that — do not over-design the trait now to avoid future changes.

End state of M1

arnes drops you into a ratatui pane; type a question; watch tokens stream into the upper region. In another terminal, echo '{"jsonrpc":"2.0",...}' | arnes-acp produces the same reply as session/update notifications. Same Session code drives both. The Frontend trait has two real consumers; the Host trait has its skeleton ready for M2's first tool.
