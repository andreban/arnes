feat/session-prompt

The translator. One method, prompt(&mut self, input), that pulls typed deltas from agent-rig, forks each one into a live SessionEvent and an accumulating ContentBlock, and on turn end emits TurnEnd { stop_reason, usage } and pushes the assembled Message onto history. The seam the architecture doc calls "the hardest concept in arnes' runtime."

Goal

Implement Session::prompt. Wire PricingRegistry into Session::new() so the translator can turn agent-rig's token counts into a TurnUsage with a real (or None) cost. Land the test that asserts the per-delta fork is the only place doing both jobs.

Files touched

  • new: crates/arnes-core/src/session/prompt.rs — the translator. (Submodule of session; impl<F, H> Session<F, H> block with the prompt method.)
  • modify: crates/arnes-core/src/session/mod.rs — mod prompt;, add pricing: PricingRegistry field, extend Session::new() with the new arg.
  • modify: crates/arnes-core/src/session/tests.rs — extend PR #2's tests to thread the new PricingRegistry arg; add the translator tests below.

No new crate deps. The StreamExt-style traits we use come from agent-rig or futures-util (transitively available via agent-rig); no direct dep needed.

Discussion

1. prompt signature. 

pub async fn prompt(&mut self, input: impl Into<String>) -> Result<()>;

impl Into<String> rather than a bespoke UserInput type: at M1 a user message is one text block, and Message::user_text(input) already exists as a convenience constructor. Introducing UserInput now would be abstraction-for-future, which the project commenting / sizing rules warn against. When M2 adds image attachments or M3 adds injected-context, the signature can grow to take a richer UserInput at that point.

The return type is Result<()> (alias for Result<(), CoreError>). The interesting outputs are side-effects: events on the frontend; mutations on self.history and self.cumulative_usage.

2. The translator: one loop, one fork. The architecture doc is emphatic on this: the translator is the single seam between streaming events and durable history. Two output channels, but exactly one place that writes to both. Schematically: 

// Pseudocode — the actual agent-rig API will shape the calls.
let mut stream = self.llm.run(messages, self.cancel_token.clone());
let mut blocks: Vec<ContentBlock> = Vec::new();

self.frontend.on_event(SessionEvent {
    agent_id: AgentId::Root, depth: 0, kind: EventKind::TurnStart,
}).await;

while let Some(delta) = stream.next().await {
    match delta {
        Ok(Delta::Text(t))     => { emit_event(TextDelta { text: t.clone() }); append_text(&mut blocks, t); }
        Ok(Delta::Thinking(t)) => { emit_event(ThinkingDelta { text: t.clone() }); append_thinking(&mut blocks, t); }
        Ok(Delta::Stop { reason, tokens, model }) => {
            let cost  = self.pricing.compute_cost(&model, &tokens);
            let usage = TurnUsage { agent_id: AgentId::Root, model, tokens, cost };
            self.cumulative_usage.record(usage.clone());
            self.history.push(Message::Assistant { content: blocks });
            emit_event(TurnEnd { stop_reason: reason, usage });
            return Ok(());
        }
        Err(e) => { emit_event(Error { message: e.to_string() }); return Err(...); }
    }
}

Two output channels (event + block-accumulator) but the one match arm per delta variant is where both happen. No other code in the crate fans this fork; M2's tool-call handling will extend the match arms in the same translator.

3. Mapping agent-rig deltas to EventKinds. agent-rig's typed-delta vocabulary is the source-of-truth shape we consume; the translator is the only place that needs to know about it. The mapping at M1 is one-to-one for the variants currently in EventKind:

agent-rig deltaEventKind emittedBlock accumulator action
text deltaTextDelta { text }append to current ContentBlock::Text, or start a new one
thinking deltaThinkingDelta { text }append to current ContentBlock::Thinking, or start a new one
stop / turn-endTurnEnd { stop_reason, usage }finalize blocks; push Message::Assistant { content: blocks }
error from streamError { message } + return Errdo not push partial blocks (see point 6)

4. Block accumulation: same-kind extends, different-kind opens. When a text delta arrives, if the last block in blocks is ContentBlock::Text, append to its text; else push a new Text block. Same logic for thinking deltas. The provider may interleave text and thinking (Gemini 2.5 reasoning does); the assembled message preserves the interleaving as separate blocks — the message-types phase deliberately picked Vec<ContentBlock> for this. A helper append_block in prompt.rs encapsulates the "extend or open" branch.

5. TurnUsage construction: pricing lookup happens here. agent-rig's stop delta carries token counts and the model identity (a ModelKey-shaped pair); PricingRegistry::compute_cost(&key, &tokens) returns Option<Cost>. That feeds straight into TurnUsage's cost field, preserving the cross-cutting "Unknown is never silently zero" invariant from phase 3. No fallback to Cost::default() — if pricing is unknown, the cost is None and CumulativeUsage::record counts it as an unknown-cost turn.

The agent identity in TurnUsage.agent_id is AgentId::Root at M1. Sub-agent attribution is a post-V1 concern.

6. Error handling: emit + return, not one or the other. If the stream yields Err(e), the translator emits EventKind::Error { message: e.to_string() } via frontend.on_event and returns Err(CoreError::Session(...)). Both channels carry the failure because each has a different audience:

  • Event channel: the frontend already renders the live transcript; users see the error in-line, after whatever partial text had already streamed.
  • Result channel: the caller (the binary's main loop) decides what to do next (retry, give up, drop the session).

Partial blocks are not pushed to history on error — the half-message would corrupt the next turn's prompt. The user-visible partial text was already streamed live, so nothing is lost; the frontend chooses how to mark the failure.

7. Cancellation: pass the token to agent-rig, do not select! here. Per the phase index's cross-cutting decision: cooperative cancellation via agent-rig. We clone self.cancel_token into the runner; when the token fires, agent-rig stops pulling from the provider and the stream ends with a "cancelled" stop variant which we map to StopReason::Cancelled. We do not wrap each stream.next().await in a select! { token.cancelled() => ..., delta = stream.next() => ... } — that would terminate the stream mid-frame and could leak agent-rig resources. M2+ may add a direct select! when a tool body itself needs to be interrupted; M1's translator stays one-loop-one-fork.

8. prompt.rs as a submodule of session. Two patterns considered:

  • One session/mod.rs: the file from PR #2 grows to include prompt. ~150 lines total. Pro: everything in one place. Con: the translator is the most subtle piece in the crate and benefits from its own file with focused comments.
  • Two files: mod.rs + prompt.rs (chosen): the struct, constructor, and accessors stay in mod.rs; the translator gets its own file with the impl block. Same crate-internal access (the submodule sees private fields of the parent module). Better local discoverability for both reading and reviewing.

9. PricingRegistry on Session::new(). PR #2's Session::new(frontend, host, llm) grows to Session::new(frontend, host, llm, pricing). Three callers to sweep: the tests in session/tests.rs from PR #2, plus the inline test fixture this PR adds. No production caller yet (binaries get wired in phase 7+). The PricingRegistry is held as an owned value, not Arc<...>, because session-pricing is per-session and not shared across sessions in M1; M6+ multi-session setups can wrap one PricingRegistry in Arc at that point and call (&*arc).clone() for each new session if needed.

    AgentId, ContentBlock, CoreError, EventKind, Frontend, Host, Message,
    Result, SessionEvent, StopReason, TurnUsage,

use super::Session;

impl<F: Frontend, H: Host> Session<F, H> {
    pub async fn prompt(&mut self, input: impl Into<String>) -> Result<()> {
        let user_msg = Message::user_text(input);
        self.history.push(user_msg.clone());

        self.frontend.on_event(event(EventKind::TurnStart)).await;

        let mut stream = /* agent-rig: run(history, cancel_token.clone()) */;
        let mut blocks: Vec<ContentBlock> = Vec::new();

        while let Some(delta) = stream.next().await {
            match delta {
                Ok(/* text */)     => { /* event + append_block */ }
                Ok(/* thinking */) => { /* event + append_block */ }
                Ok(/* stop */)     => {
                    let usage = TurnUsage { agent_id: AgentId::Root, model, tokens,
                                            cost: self.pricing.compute_cost(&model, &tokens) };
                    self.cumulative_usage.record(usage.clone());
                    self.history.push(Message::Assistant { content: blocks });
                    self.frontend.on_event(event(EventKind::TurnEnd { stop_reason, usage })).await;
                    return Ok(());
                }
                Err(e) => {
                    self.frontend.on_event(event(EventKind::Error { message: e.to_string() })).await;
                    return Err(CoreError::Session(e.to_string()));
                }
            }
        }

        // Stream ended without a Stop delta — treat as transport error.
        Err(CoreError::Session("stream ended without stop".into()))
    }
}

Tests

Three new #[tokio::test]s, plus a tiny inline test-double LlmModel at the top of session/tests.rs that emits a fixed sequence of deltas (text, text, stop). The full ScriptedLlm helper (PR #6) is not used here — this test wants minimum coupling.

  • Happy path: prompt with one text turn; assert events emitted in order (TurnStart, two TextDeltas, one TurnEnd); assert history has two entries (user + assistant); assert assistant.content is one Text block with the concatenated text; assert cumulative_usage.turns_total == 1.
  • Unknown pricing: build the session with an empty PricingRegistry::default(); assert the emitted TurnEnd.usage.cost is None and the bucket counts as turns_with_unknown_cost == 1.
  • Stream error mid-turn: scripted LLM emits one text delta then an error; assert TextDelta fires, then Error, then prompt() returns Err; assert history still has only the user message (partial assistant blocks were not pushed).
