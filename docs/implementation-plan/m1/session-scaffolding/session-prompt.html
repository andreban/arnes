feat/session-prompt

The translator. One method, prompt(&mut self, input), that pulls typed deltas from agent-rig, forks each one into a live SessionEvent and an accumulating ContentBlock, and on turn end emits TurnEnd { stop_reason, usage } and pushes the assembled Message onto history. The seam the architecture doc calls "the hardest concept in arnes' runtime."

Goal

Implement Session::prompt. Wire PricingRegistry into Session::new() so the translator can turn agent-rig's token counts into a TurnUsage with a real (or None) cost. Land the test that asserts the per-delta fork is the only place doing both jobs.

Files touched

  • new: crates/arnes-core/src/session/prompt.rs — the translator. (Submodule of session; impl<F, H> Session<F, H> block with the prompt method.)
  • modify: crates/arnes-core/src/session/mod.rs — mod prompt;, add model: ModelKey and pricing: PricingRegistry fields, extend Session::new() with the two new args.
  • modify: crates/arnes-core/src/session/tests.rs — extend PR #2's tests to thread the new args; add the translator tests below.

No new crate deps. The StreamExt-style traits we use come from agent-rig or futures-util (transitively available via agent-rig); no direct dep needed.

Discussion

1. prompt signature. 

pub async fn prompt(&mut self, input: impl Into<String>) -> Result<()>;

impl Into<String> rather than a bespoke UserInput type: at M1 a user message is one text block, and Message::user_text(input) already exists as a convenience constructor. Introducing UserInput now would be abstraction-for-future, which the project commenting / sizing rules warn against. When M2 adds image attachments or M3 adds injected-context, the signature can grow to take a richer UserInput at that point.

The return type is Result<()> (alias for Result<(), CoreError>). The interesting outputs are side-effects: events on the frontend; mutations on self.history and self.cumulative_usage.

2. The translator: one loop, one fork, plus a turn-end synthesis. The architecture doc is emphatic on the loop: the translator is the single seam between streaming events and durable history. Two output channels, but exactly one place that writes to both. Stream completion is the turn-end signal — agent-rig does not emit a turn-end event of its own — so TurnEnd is synthesised after the loop exits cleanly. Per-call AgentEvent::Usage(TokenUsage) events are buffered into a running TokenCounts; the buffered total is what feeds TurnUsage construction at synthesis time. Schematically: 

// Pseudocode — agent-rig's actual variant names shape the match arms.
let mut stream = self.runner.run_with_cancellation(
    &self.agent, self.history.clone(), self.cancel_token.clone(),
);
let mut blocks: Vec<ContentBlock> = Vec::new();
let mut tokens = TokenCounts::default();
let mut stop_reason = StopReason::EndTurn;

emit_event(EventKind::TurnStart);

while let Some(ev) = stream.next().await {
    match ev {
        AgentEvent::TextDelta(t)     => { emit_event(TextDelta { text: t.clone() }); append_text(&mut blocks, t); }
        AgentEvent::ThinkingDelta(t) => { emit_event(ThinkingDelta { text: t.clone() }); append_thinking(&mut blocks, t); }
        AgentEvent::Usage(u)         => { tokens += to_counts(u); /* buffer, no event */ }
        AgentEvent::Cancelled        => { stop_reason = StopReason::Cancelled; break; }
        AgentEvent::Error(e)         => {
            emit_event(Error { message: e.to_string() });
            return Err(CoreError::Session(e.to_string()));
        }
        // ToolCallStarted / ToolCallFinished — M2.
    }
}

let cost  = self.pricing.compute_cost(&self.model, &tokens);
let usage = TurnUsage { agent_id: AgentId::Root, model: self.model.clone(), tokens, cost };
self.cumulative_usage.record(usage.clone());
self.history.push(Message::Assistant { content: blocks });
emit_event(EventKind::TurnEnd { stop_reason, usage });
Ok(())

Two output channels (event + block-accumulator) but the one match arm per delta variant is where both happen. AgentEvent::Usage writes only to a third internal accumulator (no live event, no block); TurnEnd is the one place that reads it. M2's tool-call handling will extend the match arms in the same translator.

3. Mapping agent-rig events to EventKinds. agent-rig's AgentEvent vocabulary is the source-of-truth shape we consume; the translator is the only place that needs to know about it. The mapping at M1:

agent-rig eventEventKind emittedBlock / accumulator action
AgentEvent::TextDeltaTextDelta { text }append to current ContentBlock::Text, or start a new one
AgentEvent::ThinkingDeltaThinkingDelta { text }append to current ContentBlock::Thinking, or start a new one
AgentEvent::Usage(TokenUsage)(none)add to running TokenCounts accumulator; see point 5
AgentEvent::Cancelled(none directly)set stop_reason = Cancelled and break the loop; TurnEnd fires from the synthesis path below
AgentEvent::ErrorError { message } + return Errdo not push partial blocks (see point 6)
stream ends (no more events)TurnEnd { stop_reason, usage }finalize blocks; push Message::Assistant { content: blocks }

Three notes on shape:

  • Usage is per model call, not per turn. A multi-turn tool-using run yields multiple Usage events (one per generate_stream invocation inside agent-rig's loop). The translator sums them into one TokenCounts, which becomes the turn's TurnUsage.tokens. M2's tool-call work will exercise this multi-event path; M1's text-only turns happen to see exactly one Usage event per turn.
  • Cancelled is terminal. agent-rig emits AgentEvent::Cancelled as a best-effort terminal event when the run is cancelled (via the token or via stream-drop), then the stream ends. The translator sets the local stop_reason and breaks; the synthesis path still fires TurnEnd with whatever blocks accumulated, so the partial assistant message lands in history. (If the consumer drops the stream we never see Cancelled — the receiver is gone — but the synthesis path also never runs, which is the correct outcome.)
  • Stream ends without Cancelled or Error: that's the clean-completion case — stop_reason stays at the loop-initial EndTurn.

4. Block accumulation: same-kind extends, different-kind opens. When a text delta arrives, if the last block in blocks is ContentBlock::Text, append to its text; else push a new Text block. Same logic for thinking deltas. The provider may interleave text and thinking (Gemini 2.5 reasoning does); the assembled message preserves the interleaving as separate blocks — the message-types phase deliberately picked Vec<ContentBlock> for this. A helper append_block in prompt.rs encapsulates the "extend or open" branch.

5. TurnUsage construction: pricing lookup happens here; model identity comes from the session. agent-rig's AgentEvent::Usage carries only the token counts — not the model identity. That's deliberate upstream: the consumer already knows which model it built the runner with, so bundling it on every event would be redundant. arnes' answer is a model: ModelKey field on Session, set at construction time (point 9 below). At TurnEnd synthesis, the translator passes (&self.model, &tokens) to PricingRegistry::compute_cost; the Option<Cost> result feeds TurnUsage.cost directly, preserving the cross-cutting "Unknown is never silently zero" invariant from phase 3. No fallback to Cost::default() — if pricing is unknown, the cost is None and CumulativeUsage::record counts it as an unknown-cost turn.

The agent identity in TurnUsage.agent_id is AgentId::Root at M1. Sub-agent attribution is a post-V1 concern.

5b. TokenUsage → TokenCounts shape mismatch (decide here). agent-rig's TokenUsage and arnes' TokenCounts ship with different shapes today:

Fieldagent-rig TokenUsagearnes TokenCounts
billable input totalinput_tokens (includes cache hits)input (does not include cache)
outputoutput_tokensoutput
cache hitcached_input_tokens (subset of input_tokens)cache_read (additive — separate from input)
cache write— (not reported)cache_write
thinkingthinking_tokensthinking
tool-use prompttool_use_prompt_tokens— (no field)
none-vs-zero distinctioneach field Option<u32>each field u64

The translator has to pick a shape contract. Two options, each with consequences worth surfacing rather than burying in the to_counts helper:

  • (a) Reshape TokenCounts to match agent-rig (subset semantics; rename fields; add tool_use_prompt; drop cache_write until needed). Honest about what providers actually report at M1 (Gemini-shaped subset, no cache write); reopens phase 3's TokenCounts + Cost + ModelPricing shapes for a coordinated rename. The translator becomes a near-direct field copy with unwrap_or(0) per field. When Anthropic-style additive providers land in agent-rig, the normalisation happens at the agent-rig adapter layer (upstream's plan, per PR #31's note).
  • (b) Keep TokenCounts as-is; translator does the mapping. Map cached_input_tokens → cache_read; map input_tokens - cached_input_tokens → input (subtract so the additive invariant holds); leave cache_write = 0 and drop tool_use_prompt_tokens on the floor. Phase 3's shipped types stay stable; the mismatch is paid each turn at the seam, and the dropped dimension is invisible to the user.

The two options aren't drop-in equivalents for downstream consumers — pricing tables and any per-token-kind frontend rendering depend on which one we pick. Recommend (a): the reshape is contained (phase 3 hasn't shipped to any external caller yet), the M1 cost computation gains a real tool_use_prompt dimension when pricing tables list it, and the translator stops doing arithmetic that could drift later. If we pick (a), the reshape is its own follow-up PR (revising phase 3) and this PR builds against the reshaped TokenCounts; if we pick (b), the to_counts helper is a few lines inside this PR.

6. Error handling: emit + return, not one or the other. If the stream yields Err(e), the translator emits EventKind::Error { message: e.to_string() } via frontend.on_event and returns Err(CoreError::Session(...)). Both channels carry the failure because each has a different audience:

  • Event channel: the frontend already renders the live transcript; users see the error in-line, after whatever partial text had already streamed.
  • Result channel: the caller (the binary's main loop) decides what to do next (retry, give up, drop the session).

Partial blocks are not pushed to history on error — the half-message would corrupt the next turn's prompt. The user-visible partial text was already streamed live, so nothing is lost; the frontend chooses how to mark the failure. This is the deliberate asymmetry with the cancellation path (point 3): a cancelled message is intentional partial output and lands in history; an errored message has no clean boundary and is discarded.

7. Cancellation: pass the token to agent-rig, do not select! here. Per the phase index's cross-cutting decision: cooperative cancellation via agent-rig. We clone self.cancel_token into AgentRunner::run_with_cancellation; agent-rig takes a child_token() of it internally, so its own stream-drop cleanup never fires arnes' outer token, but the outer token firing still propagates to the child. On cancellation, agent-rig stops pulling from the provider, aborts in-flight tool futures at their next await point, and emits a terminal AgentEvent::Cancelled — the translator maps that to StopReason::Cancelled in the local stop-reason and breaks the loop. We do not wrap each stream.next().await in a select! { token.cancelled() => ..., ev = stream.next() => ... } — that would terminate the stream mid-frame and skip agent-rig's Cancelled emission, which is the authoritative signal. M2+ may add a direct select! when a tool body itself needs to be interrupted; M1's translator stays one-loop-one-fork.

Drop-the-stream is also a valid cancel trigger — agent-rig's internal DropGuard fires the child token if the consumer drops the returned stream. arnes' translator owns the stream, so this path only fires if the translator's future itself is dropped (e.g. the surrounding task is cancelled by the binary). In that case TurnEnd is never synthesised; that's the correct outcome — the session no longer has a consumer for the event.

8. prompt.rs as a submodule of session. Two patterns considered:

  • One session/mod.rs: the file from PR #2 grows to include prompt. ~150 lines total. Pro: everything in one place. Con: the translator is the most subtle piece in the crate and benefits from its own file with focused comments.
  • Two files: mod.rs + prompt.rs (chosen): the struct, constructor, and accessors stay in mod.rs; the translator gets its own file with the impl block. Same crate-internal access (the submodule sees private fields of the parent module). Better local discoverability for both reading and reviewing.

9. ModelKey + PricingRegistry on Session::new(). PR #2's Session::new(frontend, host, llm) grows to Session::new(frontend, host, llm, model, pricing). Two new args land together because the translator needs both to construct a TurnUsage: model is the ModelKey the runner was built against (agent-rig's AgentEvent::Usage deliberately omits it; the consumer is the source of truth), and pricing turns (model, tokens) into an Option<Cost>. Three callers to sweep: the tests in session/tests.rs from PR #2, plus the inline test fixture this PR adds. No production caller yet (binaries get wired in phase 7+). Both fields are held as owned values, not Arc<...>, because they're per-session and not shared across sessions in M1; M6+ multi-session setups can Arc-wrap if needed.

                /* AgentEvent::TextDelta */     => { /* event + append_block */ }
                /* AgentEvent::ThinkingDelta */ => { /* event + append_block */ }

Tests

Four new #[tokio::test]s, plus a tiny inline test-double LlmModel at the top of session/tests.rs that emits a fixed sequence of agent-rig events (text, text, usage). The full ScriptedLlm helper (PR #6) is not used here — this test wants minimum coupling.

  • Happy path: prompt with one text turn; the test double emits two TextDeltas, one Usage, then ends the stream; assert events emitted in order (TurnStart, two TextDeltas, one TurnEnd); assert history has two entries (user + assistant); assert assistant.content is one Text block with the concatenated text; assert cumulative_usage.turns_total == 1 and the recorded TokenCounts matches the emitted Usage.
  • Unknown pricing: build the session with an empty PricingRegistry::default(); assert the emitted TurnEnd.usage.cost is None and the bucket counts as turns_with_unknown_cost == 1.
  • Cancellation mid-turn: test double emits one TextDelta, one Usage, then AgentEvent::Cancelled; assert TextDelta fires, then TurnEnd { stop_reason: Cancelled, usage }; assert history has two entries (the partial assistant message is preserved, per discussion point 3); assert usage.tokens reflects the one Usage event that arrived before the cancel.
  • Stream error mid-turn: test double emits one TextDelta then AgentEvent::Error; assert TextDelta fires, then Error, then prompt() returns Err; assert history still has only the user message (partial assistant blocks were not pushed, per discussion point 6).
