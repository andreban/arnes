feat/scripted-llm

A test-only LlmModel impl (agent-rig's trait) that replays a canned sequence of typed deltas with known token counts. Drives PR #7's integration test — and any future test that needs deterministic LLM behaviour without a network call.

Goal

Ship ScriptedLlm under crates/arnes-core/tests/support/scripted_llm.rs. Configured with a vector of "turn scripts" (each turn = a list of deltas + a stop frame with token counts); each call into LlmModel's run-stream method consumes the next turn script.

Files touched

  • new: crates/arnes-core/tests/support/scripted_llm.rs — the helper.
  • modify: crates/arnes-core/tests/support/mod.rs — add pub mod scripted_llm;.
  • modify: crates/arnes-core/tests/support_smoke.rs — add helper-correctness tests.

No new deps; agent-rig is the LLM trait source.

Discussion

1. Script data shape. Two layers: 

pub struct TurnScript {
    pub deltas: Vec<ScriptedDelta>,   // text, thinking, etc.
    pub stop:   ScriptedStop,          // reason + tokens + model
}

pub enum ScriptedDelta {
    Text(String),
    Thinking(String),
}

pub struct ScriptedStop {
    pub reason: /* agent-rig stop reason */,
    pub tokens: TokenCounts,
    pub model:  ModelKey,
}

Why one struct per turn instead of a flat Vec<Delta>? Because each turn needs a stop frame with token counts attached — embedding that as just another delta variant works, but it makes "the deltas for turn 1" implicit (everything up to the next stop). The explicit TurnScript struct is also what PR #7's two-turn test will construct twice with different content.

2. Token counts are explicit on each ScriptedStop. Not derived from the deltas (e.g., "input = sum of input tokens from the history"); the test author writes them in. The translator's job is to thread the counts from agent-rig into a TurnUsage — the test exercises that threading and needs to assert on specific values. Auto-deriving from delta lengths would couple the helper to a counting convention that real providers don't share.

3. Thinking deltas at M1. Supported. The ContentBlock::Thinking variant exists in the message-types PR; EventKind::ThinkingDelta exists in the frontend PR. PR #3's translator already handles them. Including thinking deltas in the helper at M1 means PR #7's round-trip test can exercise the text-then-thinking-then-text interleaving without us adding the helper variant later.

4. Ordering / pacing. Deltas are emitted in script order, synchronously inside the stream (no tokio::time::sleep or other artificial delays). M1's translator never observes time; M2+ tests that want to exercise rate-related behaviour can add a pacing knob then.

5. Turn-script consumption: pop, not index. ScriptedLlm stores its scripts in a Mutex<VecDeque<TurnScript>>; each call into the agent-rig run-stream method pops the front turn script and streams its deltas + stop. Calling the LLM more times than scripts were provided is a panic in the helper (with a clear message). This surfaces "test under-specified the scripts" loudly instead of silently replaying or hanging.

6. Construction API. 

pub struct ScriptedLlm { /* Mutex<VecDeque<TurnScript>> */ }

impl ScriptedLlm {
    pub fn new(turns: Vec<TurnScript>) -> Self;
}

Builder API (.text("...").stop(...)) considered and rejected for M1 — the explicit struct literals are noisier to type but unambiguous to read, and PR #7 has exactly two turns to write. If a future test needs many turn scripts, a builder can be added without changing the underlying struct.

7. Coupling to agent-rig's API. Two implementation paths:

  • Implement LlmModel directly (chosen): the helper impl LlmModel for ScriptedLlm and produces a stream of agent-rig's native delta type. The translator in PR #3 sees the same shape it'd see from a real provider.
  • Implement a higher-level "Session-input" stream: skip LlmModel and hand the translator a stream of arnes types directly. Lighter for the helper, but it short-circuits the agent-rig boundary — the integration test would never exercise the LlmModel-to-translator seam, defeating the point.

We pay the cost of mapping our script types to agent-rig's so the translator sees a realistic boundary.

8. Why not a closure-based mock? impl Fn(history) -> stream is more flexible but encodes no shape; readers of a test have to follow the closure to understand what the mock does. The explicit-script shape is self-documenting in the test's source.

Code skeleton

// crates/arnes-core/tests/support/scripted_llm.rs

use std::{collections::VecDeque, sync::Mutex};

use async_trait::async_trait;

use agent_rig::LlmModel;                         // exact trait surface depends on agent-rig
use arnes_core::{ModelKey, TokenCounts};

pub struct ScriptedLlm {
    turns: Mutex<VecDeque<TurnScript>>,
}

pub struct TurnScript {
    pub deltas: Vec<ScriptedDelta>,
    pub stop:   ScriptedStop,
}

pub enum ScriptedDelta {
    Text(String),
    Thinking(String),
}

pub struct ScriptedStop {
    pub reason: /* agent-rig stop reason */,
    pub tokens: TokenCounts,
    pub model:  ModelKey,
}

impl ScriptedLlm {
    pub fn new(turns: Vec<TurnScript>) -> Self {
        Self { turns: Mutex::new(turns.into_iter().collect()) }
    }
}

#[async_trait]
impl LlmModel for ScriptedLlm {
    // The exact method here is whatever agent-rig defines on LlmModel
    // for streaming a turn. Implementation: pop the front TurnScript;
    // build a stream that yields each `deltas[i]` (mapped to agent-rig's
    // delta type), then the stop frame; return that stream.
}

Tests

Add to tests/support_smoke.rs:

  • Single turn replays in order: construct with one TurnScript of three text deltas + stop; drive the LlmModel's run; collect the emitted deltas; assert order and content.
  • Stop frame carries the configured tokens: assert the stop's tokens field matches what the test passed in.
  • Empty deltas list is OK: a TurnScript with no deltas just emits a stop — assert the stream produces exactly the stop frame.
  • Over-consumption panics with a clear message: construct with one turn; call run twice; assert the second call panics (use std::panic::catch_unwind; assert the panic message mentions "no more turn scripts" or similar).
