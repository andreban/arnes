feat/session-skeleton

The Session<F, H> struct, its constructor, the cancel-handle accessor, and a cumulative_usage() accessor. Lays down the shape that PR #3's translator hangs its prompt() on; no agent-rig pulling happens yet.

Goal

Define the load-bearing struct: its generic parameters, its fields, its constructor signature, and the two lifecycle methods that don't need the translator (cancel_handle() and cumulative_usage()). Land it with unit tests of the pieces that can be tested without an LLM, leaving prompt() for PR #3.

Files touched

  • new: crates/arnes-core/src/session/mod.rs — the struct + constructor + non-prompt methods.
  • new: crates/arnes-core/src/session/tests.rs — unit tests (per the tests-in-sibling-file convention used in metering/).
  • modify: crates/arnes-core/src/lib.rs — mod session; + pub use session::Session;.

No new deps beyond what PR #1 already added. tokio_util::sync::CancellationToken is already in tree from phase 2.

Discussion

1. Type-parameter names: F, H not F, E. The architecture doc's code blocks use Session<F: Frontend, E: Host> — E as a nod to "extension / environment." We use H for Host: it's the trait's own initial; it matches every other generic over Host already in the crate (the doc-comments in tool_context.rs refer to H: Host implicitly via Arc<dyn Host>); and the architecture doc is the one place that disagrees with itself on this name, which we'll fix as part of this PR's docs sweep.

2. Arc<F> and Arc<H>, not owned. The session needs Arc<H> because ToolContext already holds Arc<dyn Host> (phase 2), and PR #3's translator will clone the host arc to hand to each tool invocation in M2. Arc<F> is less obvious — the frontend is called from one place (the translator) inside one task — but some M3+ flows (notification-style emission from inside a tool, mid-session join in M8) need the frontend reachable from more than one task at a time. Picking Arc<F> now avoids a re-shape later. Cost: one extra atomic increment at construction; immeasurable.

3. What new() takes. The minimum set this phase needs: 

pub fn new(
    frontend: Arc<F>,
    host:     Arc<H>,
    llm:      Arc<dyn LlmModel>,   // agent-rig
) -> Self

Deliberately not taking: a ToolRegistry (empty at M1; lands in M2), a SystemPromptBuilder (M4), a SessionWriter (M6). Each of those becomes an additional new() argument in the milestone that introduces it; M1 keeps the constructor to its core three.

4. llm as Arc<dyn LlmModel>, not a generic. Three generics on Session would propagate type parameters through every helper, every test fixture, and every adapter binary; the ergonomic cost compounds fast. LlmModel is held behind an arc-dyn at the seam where agent-rig itself takes it (the AgentRunner constructor), so we don't introduce a new layer of dynamic dispatch — we mirror agent-rig's existing one. The frontend / host stay generic because the architecture doc's no-dyn-in-hot-paths promise is about those two specifically.

5. CumulativeUsage lives on the struct, not in agent-rig. Field, not method-computed. PR #3 calls cumulative_usage.record(turn) inside the translator on every TurnEnd. The accessor here is a borrowing getter: 

pub fn cumulative_usage(&self) -> &CumulativeUsage { &self.cumulative_usage }

Returning a borrow rather than a clone keeps the HashMap inside CumulativeUsage from being copied every call. Frontends that want a snapshot can clone explicitly. The ModelKey the translator builds TurnUsage with is set on the session in PR #3 (along with the prompt() method); the skeleton here just owns the running cumulative total.

6. cancel_handle(), not cancel(). A frontend wants to fire cancellation from a different task than the one driving prompt() — a Ctrl-C handler, an ACP session/cancel notification, an HTTP DELETE. prompt() takes &mut self for its history / usage mutation, so a sibling cancel(&self) method is uncallable while prompt() is awaiting (the &mut borrow excludes it). Instead, expose a cheap handle: cancel_handle(&self) -> CancellationToken returns a clone of the internal token (the token is internally arc-shared, so the clone is one atomic increment). Callers stash the handle at construction time and call handle.cancel() from any task — including while prompt() is running. agent-rig's AgentRunner sees the same cancellation via the token clone that prompt() passes it.

The architecture doc shows a session.cancel(&self) sugar method — that shape only works if Session is wrapped in Arc with interior mutability everywhere, which bloats the design for one method's ergonomics. The handle pattern is the idiomatic Rust solution; the architecture doc's sample code gets updated alongside this PR.

7. history: Vec<Message> is private. Per the architecture doc's "history vs events" split: clients never poll history; they bootstrap once at attach and stream events from then on. So Session holds history as a private field; the snapshot API that exposes it (a snapshot() method returning a shape suitable for ACP / HTTP / GUI consumers) is M6 / M8 work. M1 has no consumer that needs it. We do not introduce a placeholder snapshot() method now — it would be a half-finished implementation, which the project commenting rules warn against.

8. cancel_token field, not parameter. Two alternatives:

  • Owned by Session (chosen): the session creates a CancellationToken::new() in new(), clones it into the AgentRunner during prompt(), and cancel() fires the owned one. Caller doesn't have to plumb the token.
  • Passed in: new(..., cancel: CancellationToken). Lets the caller own cancellation (one token can cancel several sessions). Adds plumbing the caller may not want.

The session-owned variant matches the architecture doc's session.cancel() API; the caller-owned variant would bypass that method entirely. Sticking with the doc.

Code skeleton

// crates/arnes-core/src/session/mod.rs

use std::sync::Arc;

use agent_rig::LlmModel;
use tokio_util::sync::CancellationToken;

use crate::{CumulativeUsage, Frontend, Host, Message};

#[cfg(test)]
mod tests;

/// The single entry point a frontend talks to.
pub struct Session<F: Frontend, H: Host> {
    frontend:         Arc<F>,
    host:             Arc<H>,
    llm:              Arc<dyn LlmModel>,
    history:          Vec<Message>,
    cumulative_usage: CumulativeUsage,
    cancel_token:     CancellationToken,
}

impl<F: Frontend, H: Host> Session<F, H> {
    pub fn new(frontend: Arc<F>, host: Arc<H>, llm: Arc<dyn LlmModel>) -> Self {
        Self {
            frontend,
            host,
            llm,
            history: Vec::new(),
            cumulative_usage: CumulativeUsage::default(),
            cancel_token: CancellationToken::new(),
        }
    }

    pub fn cancel_handle(&self) -> CancellationToken {
        self.cancel_token.clone()
    }

    pub fn cumulative_usage(&self) -> &CumulativeUsage {
        &self.cumulative_usage
    }
}

Field visibility: all private. Crate-internal access for PR #3's translator comes from the same module file (session/prompt.rs is a submodule of session, declared in PR #3).

Tests

Three #[tokio::test] unit tests in session/tests.rs:

  • Constructor wires the fields: build a Session with mock frontend / host / LLM; assert cumulative_usage() returns a default (zero-turn) value and history is observably empty (via the fact that no event has been dispatched).
  • cancel_handle() shares cancellation: call cancel_handle() to obtain a clone, fire it, then assert that a second clone (obtained after) reports is_cancelled() == true. Confirms the handle is the internal token, not a fresh one.
  • cumulative_usage() returns an updatable borrow: not really testable without the translator; this one shrinks to a compile-only assertion that the return type is what we claim.

The mock Frontend / Host / LlmModel for these tests are inline trivial impls in tests.rs (a no-op frontend, a default LocalHost, and a panic-on-call LLM — we never invoke it in this PR's tests). The reusable test helpers (RecordingFrontend, InMemoryHost, ScriptedLlm) land in PRs #4, #5, #6.
