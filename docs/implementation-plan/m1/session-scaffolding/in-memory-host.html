feat/in-memory-host

A test-only Host impl backed by a HashMap<PathBuf, String>. Implements the fs methods (read_text_file, write_text_file, list_directory); leaves the terminal methods at the trait's default Unsupported.

Goal

Ship InMemoryHost under crates/arnes-core/tests/support/in_memory_host.rs. M1's Session never calls a host method (tools don't exist yet); the helper lands now so M2's tool tests have something to read and write against without touching the real filesystem.

Files touched

  • new: crates/arnes-core/tests/support/in_memory_host.rs — the helper.
  • modify: crates/arnes-core/tests/support/mod.rs — uncomment / add pub mod in_memory_host;.
  • modify: crates/arnes-core/tests/support_smoke.rs — add the helper's own correctness tests next to RecordingFrontend's.

No new deps.

Discussion

1. Why this helper exists at M1 when no test uses it yet. Strictly, phase 4's only consumer is PR #7's session round-trip test — which doesn't fire any tool, so doesn't touch the host. But the cross-cutting decision in the phase index is that the test scaffolding lands as a coherent set in phase 4; deferring InMemoryHost to "the first PR that needs it" would mean re-doing the test-support discussion when M2 lands. We pay the small cost of one unused-helper PR now so M2's tool tests can just import the helper.

2. Backing storage: Mutex<HashMap<PathBuf, String>>. Simplest data shape that supports the three fs methods. Paths are stored as-given (no canonicalisation, no cwd resolution); the test is responsible for using absolute paths consistently. list_directory filters the keys whose parent equals the queried path; entry kind is always is_dir: false at M1 because the store has no notion of directories (every entry is a leaf file). M3 expands this when real directory semantics start to matter for tests.

3. Terminal methods deliberately not implemented. The Host trait's terminal methods (terminal_create, terminal_snapshot, terminal_kill, terminal_release) default to io::ErrorKind::Unsupported. InMemoryHost leaves those defaults in place. Two reasons:

  • No M1 test exercises them. Bash tool lands in M2; even then it's only invoked through LocalHost for the smoke test, not through the in-memory host.
  • Faking a terminal is hard to do shallowly. A useful fake terminal needs scripted output, exit codes, and timing — that's a separate helper, not a one-line addition to InMemoryHost. Better to acknowledge that gap now than to ship a half-faked terminal that mis-leads M2's tests.

Tests that need a terminal will get a separate ScriptedTerminal helper in M2 alongside the bash tool.

4. Seeding initial files. Two patterns considered:

  • Constructor seeds: InMemoryHost::with_files(initial: impl IntoIterator<Item = (PathBuf, String)>). Tests pre-populate at construction.
  • Mutation methods on the helper: host.put(path, contents) outside the trait. Lets tests add files at any point.

We ship both: new() for empty; with_files(...) for the common "seed and run" case; put(path, contents) for the "mutate mid-test" case (M2's tool tests will use this). Cheap to add all three now; each is one line of code.

5. std::sync::Mutex again. Same reasoning as RecordingFrontend: the lock is held only across pure-data ops (HashMap::get, HashMap::insert, HashMap::values()). No .await while locked.

6. Error shapes match LocalHost's eventual behaviour. Missing file: io::ErrorKind::NotFound. List of a path that has no children: Ok(Vec::new()) — not an error. (The trait method returns Vec<DirEntry>; empty is the natural representation of "no entries.") Mismatching these to what LocalHost will do in M3 would create tests that pass against the fake and fail against real fs.

Code skeleton

// crates/arnes-core/tests/support/in_memory_host.rs

use std::{
    collections::HashMap,
    io,
    path::{Path, PathBuf},
    sync::Mutex,
};

use async_trait::async_trait;

use arnes_core::{DirEntry, Host};

#[derive(Default)]
pub struct InMemoryHost {
    files: Mutex<HashMap<PathBuf, String>>,
}

impl InMemoryHost {
    pub fn new() -> Self { Self::default() }

    pub fn with_files(initial: impl IntoIterator<Item = (PathBuf, String)>) -> Self {
        Self {
            files: Mutex::new(initial.into_iter().collect()),
        }
    }

    pub fn put(&self, path: PathBuf, contents: String) {
        self.files
            .lock()
            .expect("in-memory-host mutex poisoned")
            .insert(path, contents);
    }
}

#[async_trait]
impl Host for InMemoryHost {
    async fn read_text_file(&self, path: &Path) -> io::Result<String> {
        self.files
            .lock()
            .expect("in-memory-host mutex poisoned")
            .get(path)
            .cloned()
            .ok_or_else(|| io::Error::new(io::ErrorKind::NotFound, "no such file"))
    }

    async fn write_text_file(&self, path: &Path, contents: &str) -> io::Result<()> {
        self.files
            .lock()
            .expect("in-memory-host mutex poisoned")
            .insert(path.to_path_buf(), contents.to_string());
        Ok(())
    }

    async fn list_directory(&self, path: &Path) -> io::Result<Vec<DirEntry>> {
        let map = self.files.lock().expect("in-memory-host mutex poisoned");
        let mut out = Vec::new();
        for stored in map.keys() {
            if stored.parent() == Some(path) {
                let name = stored.file_name().and_then(|s| s.to_str()).unwrap_or("").to_string();
                out.push(DirEntry { name, is_dir: false });
            }
        }
        Ok(out)
    }

    // terminal_* methods inherit Unsupported defaults.
}

Tests

Extend tests/support_smoke.rs with:

  • Read after write: write a path, read it back, assert the contents match.
  • Missing file → NotFound: read an unseeded path; assert err.kind() == io::ErrorKind::NotFound.
  • List directory: seed three files under /a/, list /a/; assert three entries (any order) and all have is_dir == false.
  • Terminal still Unsupported: call terminal_create with a dummy spec; assert err.kind() == io::ErrorKind::Unsupported — confirms we didn't accidentally override the default.
