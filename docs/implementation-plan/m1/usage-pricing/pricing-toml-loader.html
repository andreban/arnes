feat/pricing-toml-loader

TOML schema + loader. Reads the bundled arnes-core/data/pricing.toml and the optional user override at ~/.arnes/pricing.toml, hands the parsed rules to PricingRegistry::from_rules (PR #5).

Goal

Define the on-disk TOML shape for pricing data; ship the loader that parses bundled + user files into Vec<Rule>s consumable by the registry. Seed the bundled file with the Gemini model(s) M1 uses and the Ollama wildcard.

Files touched

  • new: crates/arnes-core/data/pricing.toml — bundled pricing seed.
  • new: code for the loader (in pricing.rs alongside the registry, or a sibling pricing/loader.rs if it gets long — one-file judgment call).
  • modify: crates/arnes-core/src/lib.rs — re-export the loader entry point.
  • modify: root + arnes-core Cargo.toml — add toml dep.

Discussion

1. TOML schema. Array-of-tables form: 

# Bundled at crates/arnes-core/data/pricing.toml
# User override at ~/.arnes/pricing.toml uses the same schema.

[[model]]
provider             = "gemini"
id                   = "gemini-2.5-flash"
input_per_mtok       = 0.075       # USD per million tokens
output_per_mtok      = 0.30
cache_read_per_mtok  = 0.01875

[[model]]
provider = "ollama"
pattern  = "*"
cost     = "free"

Each [[model]] entry has:

  • provider (required).
  • Exactly one of id (exact match) or pattern (wildcard — M1 supports only "*").
  • Exactly one of: a cost = "free" tag, or the per-mtok rate fields (input_per_mtok, output_per_mtok required; cache_read_per_mtok, cache_write_per_mtok, thinking_per_mtok optional). Absent of both means Unknown — but unknown entries aren't worth declaring, so the loader rejects them.

Rates in the TOML are f64 dollars-per-Mtok (so the file stays human-readable: 0.075 instead of 75); the loader converts to Micros at parse time (round(dollars * 1_000_000) = micros-per-Mtok).

2. Bundling: include_str! at compile time. Two options for shipping the bundled TOML:

  • Embed via include_str! (chosen). The file content is baked into the binary at compile time; no runtime file lookup. Works on every platform without thinking about install paths.
  • Runtime read from a known path. Requires knowing where the data file is installed (next to the binary? in a cargo target dir?); complicates cargo install for downstream users.

include_str! is the right call for a small static asset. The user override at ~/.arnes/pricing.toml is read at runtime since it's user-controlled and per-machine.

3. User-override location. ~/.arnes/pricing.toml — same root as the rest of arnes' per-user state (sessions land there at M6, skills at M5). The loader uses dirs::home_dir() or std::env::home_dir() (stabilised in recent rustc) to find ~; missing file is non-fatal (treated as empty override).

4. toml dep choice. The toml crate is the obvious choice: serde-compatible, well-maintained, ~standard in the Rust ecosystem. Alternatives (basic-toml, hand-parsed) earn their place only if dep weight matters; it doesn't here. Add to workspace + crate deps.

5. Parse errors. Loader returns (Vec<Rule>, Vec<Diagnostic>) rather than Result: a malformed entry shouldn't abort loading the rest of the file. The bundled file should parse cleanly (we author it); a malformed user override should warn but not break the session. Diagnostic is a simple { source: PathBuf, message: String }.

6. The top-level load_pricing entry. Single function that:

  1. Parses the bundled TOML via include_str!.
  2. Looks for ~/.arnes/pricing.toml; parses if present.
  3. Returns a PricingRegistry built from both rule sets, plus any diagnostics for callers (frontends, logs) to surface.

Loader (sketched, in pricing.rs or a sibling module):

use std::path::PathBuf;
use serde::Deserialize;

#[derive(Debug, Default)]
pub struct LoadDiagnostic {
    pub source:  PathBuf,
    pub message: String,
}

pub fn load_pricing() -> (PricingRegistry, Vec<LoadDiagnostic>) {
    let mut diagnostics = Vec::new();

    let bundled_src = include_str!("../data/pricing.toml");
    let bundled = parse_rules(bundled_src, PathBuf::from("<bundled>"), &mut diagnostics);

    let user_path = user_override_path();
    let user = match user_path.as_ref().and_then(|p| std::fs::read_to_string(p).ok()) {
        Some(src) => parse_rules(&src, user_path.unwrap(), &mut diagnostics),
        None      => Vec::new(),
    };

    (PricingRegistry::from_rules(bundled, user), diagnostics)
}

fn user_override_path() -> Option<PathBuf> {
    std::env::home_dir().map(|h| h.join(".arnes").join("pricing.toml"))
}

#[derive(Deserialize)]
struct TomlFile {
    #[serde(default)]
    model: Vec<TomlModel>,
}

#[derive(Deserialize)]
struct TomlModel {
    provider:             String,
    id:                   Option<String>,
    pattern:              Option<String>,
    cost:                 Option<String>,        // "free" or absent
    input_per_mtok:       Option<f64>,
    output_per_mtok:      Option<f64>,
    cache_read_per_mtok:  Option<f64>,
    cache_write_per_mtok: Option<f64>,
    thinking_per_mtok:    Option<f64>,
}

fn parse_rules(src: &str, source: PathBuf, diagnostics: &mut Vec<LoadDiagnostic>) -> Vec<Rule> {
    let parsed: TomlFile = match toml::from_str(src) {
        Ok(p) => p,
        Err(e) => {
            diagnostics.push(LoadDiagnostic { source, message: format!("toml parse error: {e}") });
            return Vec::new();
        }
    };

    let mut rules = Vec::with_capacity(parsed.model.len());
    for (i, m) in parsed.model.into_iter().enumerate() {
        match build_rule(m) {
            Ok(r)  => rules.push(r),
            Err(e) => diagnostics.push(LoadDiagnostic {
                source: source.clone(),
                message: format!("entry [{i}]: {e}"),
            }),
        }
    }
    rules
}

// build_rule: validates "exactly one of id/pattern"; "exactly one of
// cost/rates"; converts f64 dollars to Micros; constructs Rule.

Tests

  • Parse the bundled file: load_pricing() succeeds with no diagnostics; the resulting registry resolves gemini-2.5-flash to a Priced entry and any ollama model to Free.
  • Parse a malformed entry: a TOML with one valid and one missing-required-field entry returns the one valid rule + one diagnostic.
  • User override wins: parse a fake "user" TOML that re-declares gemini-2.5-flash with different rates; the merged registry uses the user rates.
  • f64 → Micros conversion: input_per_mtok = 0.075 in TOML produces Micros(75) in the rule.
  • Missing user file is non-fatal: when no ~/.arnes/pricing.toml exists, load_pricing() returns the bundled registry + no diagnostics.
