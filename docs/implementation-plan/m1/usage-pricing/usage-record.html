feat/usage-record

Usage (the per-turn record) and ModelUsage (the aggregated-row shape that CumulativeUsage stores per bucket in PR #4).

Goal

Define the per-turn usage record and the aggregated row shape it folds into.

Files touched

  • modify: crates/arnes-core/src/usage.rs — append Usage + ModelUsage.
  • modify: crates/arnes-core/src/lib.rs — re-export.

No new deps.

Discussion

1. When is Cost computed? Two options:

  • Eager (at Usage construction): caller (Session, phase 4) looks up the PricingRegistry when the turn ends, computes Cost, and builds the Usage with cost: Some(cost) (or None for Unknown). Chosen.
  • Lazy (Usage holds raw tokens only; cost computed on demand): Usage doesn't carry a cost field at all. Anyone wanting cost calls registry.compute(usage). Cleaner separation, but: every consumer (frontend display, persistence rows in M6, ACP usage frames) would need access to the registry. The registry would have to be threadable through every consumer. Heavy.

Eager wins because Usage ends up flowing to many consumers (events, history, persistence) and we'd rather compute the cost once at the boundary with the registry than thread the registry everywhere.

2. cost: Option<Cost> rationale. Option here means "we couldn't compute cost for this turn" — specifically because the model's ModelCostInfo was Unknown in the registry. Free models produce Some(Cost::default()) (all zeros, total zero), distinguishable from None at the consumer level.

Mapping is:

  • ModelCostInfo::Priced(p) → Some(compute(tokens, p))
  • ModelCostInfo::Free → Some(Cost::default())
  • ModelCostInfo::Unknown → None

3. Usage carries agent_id and ModelKey. Already established in core.html's future-compat table: every Usage is tagged with which agent produced it and which model it was billed to. Phase 4's Session sets these at the boundary; CumulativeUsage (PR #4) uses the (agent_id, model) pair as its hash-map key.

4. ModelUsage shape. One bucket's aggregated state — what CumulativeUsage stores per (AgentId, ModelKey) key:

  • Sum of every token-kind across all turns in this bucket.
  • Turn count.
  • Sum of known cost (across turns where Usage.cost was Some(...)).
  • Count of turns where Usage.cost was None — tracked separately so the consumer can show "5 turns with unknown pricing" rather than coercing them into the cost sum.

The model: ModelKey field on ModelUsage duplicates the half of the map key, which makes flattened views (PR #7) cleaner: a by_model() result is a list of ModelUsage values that already know which model they're about.

Code skeleton

// Appended to crates/arnes-core/src/usage.rs:

use crate::{AgentId, ModelKey};

/// What a single turn cost.
#[derive(Clone, Debug)]
pub struct Usage {
    pub agent_id:           AgentId,
    pub model:              ModelKey,
    pub input_tokens:       u64,
    pub output_tokens:      u64,
    pub cache_read_tokens:  u64,
    pub cache_write_tokens: u64,
    pub thinking_tokens:    u64,
    /// `None` when the model's pricing is `ModelCostInfo::Unknown`.
    pub cost: Option<Cost>,
}

/// One bucket's aggregated state in `CumulativeUsage`.
#[derive(Clone, Debug)]
pub struct ModelUsage {
    pub model:                   ModelKey,
    pub input_tokens:            u64,
    pub output_tokens:           u64,
    pub cache_read_tokens:       u64,
    pub cache_write_tokens:      u64,
    pub thinking_tokens:         u64,
    pub turns:                   u32,
    pub known_cost:              Cost,
    pub turns_with_unknown_cost: u32,
}
