feat/pricing-types

ModelPricing (per-token-kind rates) and ModelCostInfo (the three-state Priced / Free / Unknown tag that wraps it).

Goal

Define the pricing data shapes the registry (PR #5) and cost computation (PR #3's caller) consume.

Files touched

  • modify: crates/arnes-core/src/usage.rs — append ModelPricing + ModelCostInfo.
  • modify: crates/arnes-core/src/lib.rs — re-export the new types.

No new deps.

Discussion

1. Three-state ModelCostInfo vs Option<ModelPricing>. The natural Rust idiom would be Option<ModelPricing>: Some(pricing) means we have pricing, None means we don't. But we have three distinct meanings, not two:

  • Priced: we know the price (use the rates).
  • Free: the model is explicitly free (e.g. local Ollama). Cost is genuinely $0.00, not "unknown."
  • Unknown: we don't have pricing data. Cost is unknown, not zero.

Collapsing Free and Unknown both into None would lose the distinction between "we know this is free" and "we don't know what it costs." Frontends rendering usage want to display these differently: Free can show "$0.00" with confidence; Unknown should show "—" or "unknown" rather than misleading the user.

The phase cross-cutting decision — "Unknown is never silently zero" — rests on this enum staying three-state.

2. Per-mtok rates in Micros. Provider pricing is published in dollars-per-million-tokens (e.g. Gemini 2.5 Flash: $0.075 input / $0.30 output per Mtok). Storing those as Micros gives:

  • $0.075/Mtok = 75 micros/Mtok — clean integer.
  • Cost computation is tokens * micros_per_mtok / 1_000_000, all integer math.
  • If a provider ever publishes a rate that doesn't fit in micros at Mtok scale (unlikely — that'd be 9 trillion dollars per token), the load-time TOML parse catches it; we'd revisit.

3. Optional cache / thinking pricing fields. Not every model has cache pricing (only providers that expose prompt caching) or thinking-token pricing (only models with extended thinking). Two ways to model the absence:

  • Option<Micros> per optional rate (chosen). None means "no separate rate." For cache, that typically means cache_read bills at the regular input rate (no discount); for thinking, it means thinking tokens bill at the regular output rate. The pricing computation does the fallback.
  • Micros defaulting to the regular rate. Simpler arithmetic, but loses the "this provider doesn't have a cache discount" information from the TOML — you can't tell apart "cache_read is the same as input" (no discount) from "cache_read happens to equal input at this rate" (with discount).

Option wins because the TOML stays honest about what the provider documents.

4. Free vs Priced(all_zeros). An alternative to a Free variant would be Priced(ModelPricing { input_per_mtok: Micros::ZERO, output_per_mtok: Micros::ZERO, ... }). Functionally equivalent for computation, but semantically lossy: a display layer can show "Free" with a confident label rather than "$0.000000 / 1M tokens" four times. Keeping Free as a distinct variant makes the user-facing rendering trivial.

Code skeleton

// Appended to crates/arnes-core/src/usage.rs:

/// Per-million-token rates for a model.
#[derive(Clone, Debug)]
pub struct ModelPricing {
    pub input_per_mtok:       Micros,
    pub output_per_mtok:      Micros,
    pub cache_read_per_mtok:  Option<Micros>,
    pub cache_write_per_mtok: Option<Micros>,
    pub thinking_per_mtok:    Option<Micros>,
}

/// What we know about a model's cost.
#[derive(Clone, Debug)]
pub enum ModelCostInfo {
    Priced(ModelPricing),
    Free,
    Unknown,
}
