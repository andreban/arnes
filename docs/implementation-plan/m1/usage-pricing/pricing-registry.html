feat/pricing-registry

PricingRegistry — in-memory lookup of ModelCostInfo by (provider, model_id), organised as a provider map where each provider carries a default plus a per-model override table. JSON parsing into this shape lands in PR #6; this PR ships the registry types, lookup, and compute_cost.

Goal

Ship the data structure callers consult to turn a ModelKey + raw token counts into a ModelCostInfo (and from there, an Option<Cost>). Construction takes pre-grouped provider blocks; the JSON parser that produces them lands in PR #6.

Files touched

  • new: crates/arnes-core/src/pricing.rs — ProviderPricing, PricingRegistry, lookup, compute_cost.
  • modify: crates/arnes-core/src/usage.rs — add TokenCounts + ModelPricing::cost_for + private scale_per_mtok; add #[derive(Default)] to ModelCostInfo with Unknown as the default variant (lets ProviderPricing derive Default).
  • modify: crates/arnes-core/src/lib.rs — module + re-exports.

No new deps.

Discussion

1. Why per-provider defaults instead of wildcards. An earlier sketch of this PR had a Matcher::Pattern("*") rule alongside Matcher::Exact(model_id) — the idea being that the bundled Ollama rule could match any model_id via provider = "ollama", pattern = "*". We replaced that with an explicit per-provider default for two reasons:

  • Wildcards have one safe use case and many dangerous ones. The only practical wildcard in this domain is "this whole provider is free" (Ollama, llama.cpp, LocalAI — the harness can't enumerate model_ids ahead of time). Wildcards on paid providers are actively harmful: a ("gemini", "2.5-*") rule would mask the wide pricing spread between flash / pro / nano and silently produce wrong totals.
  • Per-provider defaults say what they mean. "Ollama defaults to Free" is what we actually want to express. pattern = "*" invites the reader (or a future contributor) to imagine glob support exists when it doesn't, and to write rules that look reasonable but mis-price.

2. Internal structure: one map, provider-grouped. The registry is a single map keyed by provider name; each entry holds the provider's default ModelCostInfo plus a per-model override table. 

pub struct ProviderPricing {
    pub default: ModelCostInfo,
    pub models:  HashMap<String, ModelCostInfo>,
}

pub struct PricingRegistry {
    providers: HashMap<String, ProviderPricing>,
}

An earlier draft used two independently-keyed maps (exact: HashMap<(String, String), ModelCostInfo> and provider_default: HashMap<String, ModelCostInfo>) plus a PricingEntry enum that the loader produced and from_entries dispatched into the two maps. The provider-grouped shape collapses both data structures into one, drops the enum entirely, and makes the registry's natural input the same provider-block shape PR #6's JSON loader already deserializes into. No flattening pass on the loader side, no dispatch match on the registry side.

ModelCostInfo::Unknown is the Default variant of the enum (the doc lists this under "Files touched"). A ProviderPricing with no declared default therefore reads as "this provider has no fallback price" — which is what Unknown already means.

3. Lookup precedence. Per-model entry wins; provider default is the fallback; missing provider is Unknown.

  1. If providers[key.provider] is absent: return ModelCostInfo::Unknown.
  2. Else if providers[key.provider].models[key.model_id] exists: return it.
  3. Else: return providers[key.provider].default.

"Per-model entry beats provider default" is no longer a separate contract — it's a property of checking the inner map before falling back to the outer default.

4. Construction and merge. User overrides win. The construction API: 

pub fn from_providers(
    blocks: impl IntoIterator<Item = (String, ProviderPricing)>,
) -> Self;

Internal merge: HashMap::insert on the provider key. Later blocks in the iterator replace earlier blocks for the same provider atomically — the new ProviderPricing takes over (its default and its models); the earlier block's models do not survive. A caller that wants finer-grained merging composes the blocks themselves before handing them to from_providers; the registry doesn't try to reach into per-provider state.

Atomic per-provider replacement is fine because at M1 there is only one input source (the user's ~/.arnes/pricing.json; see PR #6 for why we don't bundle defaults). If a user writes two blocks for the same provider in their JSON, the file is malformed in spirit — "last wins entirely" is a defensible reading.

5. compute_cost on the registry; cost_for on ModelPricing. The work splits in two, each method living on the type that owns its data:

  • PricingRegistry::compute_cost(&self, key, tokens) -> Option<Cost> does lookup + three-state dispatch.
  • ModelPricing::cost_for(&self, tokens) -> Cost does the per-token-kind integer arithmetic.

compute_cost is a thin wrapper: None for Unknown, Some(Cost::default()) for Free, Some(pricing.cost_for(tokens)) for Priced. Caller shape is one call: let cost = registry.compute_cost(&model, tokens);.

The arithmetic is straightforward integer math: per token kind, (tokens * micros_per_mtok) / 1_000_000, with an i128 intermediate to avoid overflow. For optional rates (cache_read_per_mtok etc.), fall back to the matching base rate (input_per_mtok for cache, output_per_mtok for thinking).

Why not impl Mul<u64> for Micros? Because the operation isn't multiplication — it's "rate × quantity ÷ 1,000,000" (rates are per-million-tokens). Micros(75) * 1_000_000 could reasonably mean either "75 micros, a million times → $75" or "75 µ/Mtok × 1M tokens → $0.000075." Hiding that gap behind * is the operator-overloading anti-pattern. Micros also already implements Add for cost aggregation; layering Mul on top would conflate two different concepts (cost vs. rate) on the same type. A method on the rate-owning type (ModelPricing::cost_for) names the operation, keeps the / 1_000_000 in one place, and avoids needing a separate wrapper type (MicrosPerMtok) just to disambiguate.

6. Where is the registry constructed? Not in M1's ToolContext or per-tool scope; it lives session-wide. Phase 4 builds one PricingRegistry at Session::new and shares it for the session's lifetime. M1's registry struct doesn't need to be Sync-by-default since it's immutable post-load (we'd reach for Arc<PricingRegistry> at the call sites if shared), but the type derives Clone for flexibility.

Appended to crates/arnes-core/src/usage.rs (near ModelPricing):

/// Per-token-kind counts a turn consumed.
#[derive(Clone, Copy, Debug, Default)]
pub struct TokenCounts {
    pub input:       u64,
    pub output:      u64,
    pub cache_read:  u64,
    pub cache_write: u64,
    pub thinking:    u64,
}

impl ModelPricing {
    /// Compute the cost of a turn's token counts under this pricing.
    /// Optional cache / thinking rates fall back to the matching base
    /// rate (`input_per_mtok` for cache, `output_per_mtok` for thinking).
    pub fn cost_for(&self, tokens: &TokenCounts) -> Cost {
        let input       = scale_per_mtok(tokens.input,       self.input_per_mtok);
        let output      = scale_per_mtok(tokens.output,      self.output_per_mtok);
        let cache_read  = scale_per_mtok(
            tokens.cache_read,
            self.cache_read_per_mtok.unwrap_or(self.input_per_mtok),
        );
        let cache_write = scale_per_mtok(
            tokens.cache_write,
            self.cache_write_per_mtok.unwrap_or(self.input_per_mtok),
        );
        let thinking    = scale_per_mtok(
            tokens.thinking,
            self.thinking_per_mtok.unwrap_or(self.output_per_mtok),
        );
        let total = input + output + cache_read + cache_write + thinking;
        Cost { input, output, cache_read, cache_write, thinking, total }
    }
}

// (tokens * micros_per_mtok) / 1_000_000, with i128 intermediate to
// avoid overflow at large token counts.
fn scale_per_mtok(tokens: u64, per_mtok: Micros) -> Micros {
    let product = (tokens as i128) * (per_mtok.0 as i128);
    Micros((product / 1_000_000) as i64)
}

// Copyright 2026 Andre Cipriani Bandarra
// SPDX-License-Identifier: Apache-2.0

//! Pricing registry: lookup of `ModelCostInfo` by `(provider, model_id)`.

use std::collections::HashMap;

use crate::{Cost, ModelCostInfo, ModelKey, TokenCounts};

/// Pricing for one provider: a default that applies when no per-model
/// entry matches, plus the per-model overrides.
#[derive(Clone, Debug, Default)]
pub struct ProviderPricing {
    pub default: ModelCostInfo,
    pub models:  HashMap<String, ModelCostInfo>,
}

#[derive(Clone, Debug, Default)]
pub struct PricingRegistry {
    providers: HashMap<String, ProviderPricing>,
}

impl PricingRegistry {
    /// Build a registry from provider blocks. If the same provider name
    /// appears twice, the later block replaces the earlier one entirely.
    pub fn from_providers(
        blocks: impl IntoIterator<Item = (String, ProviderPricing)>,
    ) -> Self {
        PricingRegistry { providers: blocks.into_iter().collect() }
    }

    /// Look up the cost info for a `ModelKey`. A per-model entry wins;
    /// the provider's default is the fallback; missing providers resolve
    /// to `Unknown`.
    pub fn lookup(&self, key: &ModelKey) -> ModelCostInfo {
        let Some(p) = self.providers.get(&key.provider) else {
            return ModelCostInfo::Unknown;
        };
        p.models
            .get(&key.model_id)
            .cloned()
            .unwrap_or_else(|| p.default.clone())
    }

    /// Compute the cost for a turn given the model and its raw token
    /// counts. Returns `None` when the model's pricing is `Unknown`.
    pub fn compute_cost(&self, key: &ModelKey, tokens: &TokenCounts) -> Option<Cost> {
        match self.lookup(key) {
            ModelCostInfo::Unknown   => None,
            ModelCostInfo::Free      => Some(Cost::default()),
            ModelCostInfo::Priced(p) => Some(p.cost_for(tokens)),
        }
    }
}

Tests

  • Per-model match: a provider block with a model entry for "gemini-2.5-flash" matches that exact key; doesn't match "gemini-2.5-pro" on the same provider when the default is Unknown.
  • Provider default match: a provider block with default = Free and empty models matches every model_id under that provider.
  • Per-model beats provider default: a provider block with default = Free plus a model entry for "billed-model" with Priced resolves "billed-model" to Priced and anything else under that provider to Free.
  • Unmatched provider returns Unknown: a registry built with no blocks for "nobody" resolves (nobody, anything) to ModelCostInfo::Unknown.
  • Later provider block replaces earlier: passing two blocks for "gemini" in from_providers — the first with default = Free and one model, the second with default = Unknown and a different model — resolves only what the second block declared, not the first.
  • compute_cost three-state: a model resolving to Priced returns Some with computed amounts; Free returns Some(Cost::default()); Unknown returns None.
  • compute_cost optional fallback: a Priced entry with cache_read_per_mtok = None bills cache_read tokens at input_per_mtok.
  • Arithmetic: 75 micros/Mtok × 1,000,000 tokens = Micros(75) (a.k.a. $0.000075).
