M1 · Phase 3 · PR 8 of 8

feat/turnend-usage-wiring

Adds the usage: TurnUsage field to EventKind::TurnEnd. Closes phase 3 by giving the runtime layer (phase 4) a place to emit per-turn usage on every turn end. Emission itself lands in phase 4 with Session.

Goal

One-field addition to EventKind::TurnEnd, plus the in-tree consumer sweep. No new construction sites (nothing in M1 constructs TurnEnd yet).

Files touched

  • modify: crates/arnes-core/src/frontend.rs — the variant change.

No new deps, no new modules, no new tests for this PR (the type change is data-only; phase 4's session_roundtrip test will exercise the new field).

Discussion

1. The one-line change. 

// Before:
TurnEnd { stop_reason: StopReason },

// After:
TurnEnd { stop_reason: StopReason, usage: TurnUsage },

This is a breaking variant-shape change. Per the phase-2 cross-cutting decision, EventKind is not #[non_exhaustive] on purpose — the compiler surfaces every match site that needs updating.

2. Consumer sweep. At this PR, the only in-tree consumers of EventKind::TurnEnd are: nothing. Phase 4's recording_frontend (test helper), scripted_llm (test helper), and Session::prompt all construct TurnEnd — but those don't exist yet. So this PR is, mechanically, just the variant edit.

If a future PR adds a consumer before this one lands, the order would flip (the consumer PR builds against the not-yet-extended variant); this PR's order in phase 3 reflects the no-consumers-yet reality.

3. Why ship this as its own PR rather than fold it into a future phase 4 PR? Two reasons:

  • Phase boundary cleanliness. Phase 3's job is to land the usage vocabulary. Wiring it into the event type is part of that vocabulary commitment, even if no producer yet exists.
  • Plan integrity. Anyone reading EventKind after phase 3 sees the field, immediately understands "TurnEnd carries TurnUsage" without having to find where it gets added later. Splitting type-vocabulary work from runtime work matches how phase 2 worked.

4. Field order. stop_reason first (the existing field), usage appended. Cosmetic; either order works.

Code skeleton

The only meaningful change:

// In crates/arnes-core/src/frontend.rs:

use crate::TurnUsage;   // new import

// In the EventKind enum:
TurnEnd {
    stop_reason: StopReason,
    usage: TurnUsage,
},

Tests

None new in this PR. The type change has no behaviour to test on its own; EventKind is a pure-data enum. Phase 4's session_roundtrip test exercises TurnEnd construction and consumption with real (scripted-LLM) usage values.
