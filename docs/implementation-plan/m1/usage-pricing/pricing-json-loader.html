feat/pricing-json-loader

JSON schema for the user-supplied ~/.arnes/pricing.json, parsed directly into a PricingRegistry (PR #5). No bundled defaults — fresh installs resolve every model to ModelCostInfo::Unknown until the user opts in.

Goal

Define the on-disk JSON shape for pricing data and the deserialize-time conversion from human-readable dollars-per-Mtok to Micros. The PR ships schema structs and serde derives; file-system wiring (where the file lives, when it's read, missing-file policy) is deferred to whichever later PR plugs the registry into a Session.

Files touched

  • modify: crates/arnes-core/src/pricing.rs — add parse_pricing plus the ProviderBlock / ModelEntry deserialize shapes; add #[derive(Deserialize)] to ModelCostInfo.
  • modify: crates/arnes-core/src/usage.rs — add #[serde(from = "Rates")] to ModelPricing plus the Rates mirror struct and its From impl.
  • modify: crates/arnes-core/src/lib.rs — re-export parse_pricing.

No new deps — serde_json is already a workspace dependency.

Discussion

1. JSON schema. The top level is an array of provider blocks. Each block has provider, an optional default (the per-provider fallback), and an optional models array. Models inline their rates directly. 

// ~/.arnes/pricing.json
[
  {
    "provider": "gemini",
    "models": [
      {
        "id": "gemini-2.5-flash",
        "input_per_mtok": 0.075,
        "output_per_mtok": 0.30,
        "cache_read_per_mtok": 0.01875
      },
      {
        "id": "gemini-2.5-pro",
        "input_per_mtok": 1.25,
        "output_per_mtok": 5.0
      }
    ]
  },
  {
    "provider": "ollama",
    "default": "free"
  }
]

Each model entry's rate fields: input_per_mtok and output_per_mtok are required; cache_read_per_mtok, cache_write_per_mtok, thinking_per_mtok are optional and fall back to the matching base rate in ModelPricing::cost_for (see PR #5). Rates are f64 dollars-per-Mtok in the file (human-readable); the loader converts to Micros at parse time (round(dollars * 1_000_000)).

default uses externally-tagged ModelCostInfo: "free" for the unit variant, {"priced": {...rates...}} for a self-hosted-but-paid endpoint. The Unknown variant is not user-declarable — an entry the user can't describe isn't one they'd write.

2. Why this shape: provider-grouped, structurally typed. Earlier drafts used a flat array where every row carried its provider string and a "kind" tag to distinguish exact entries from provider defaults. Grouping by provider eliminates the repeated provider field and lets the exact-vs-default distinction be structural (top-level default field vs. entry in models) rather than nominal. Combined with externally-tagged ModelCostInfo for the default value, every illegal combination is unrepresentable — no hand-written validator, no shared all-Optional struct, no "did you forget exactly one of these fields" check. Serde's "did this parse?" is the validation.

One thing the shape deliberately under-expresses: a single free model on an otherwise paid provider. That's rare enough not to design for — free models are virtually always provider-level (Ollama, llama.cpp, LocalAI). If anyone hits the case, adding a "free": true opt to model entries is additive.

3. Why JSON over TOML. Originally drafted in TOML for human-editability. Switched to JSON because serde_json is already a workspace dep (TOML would add one), and the file is small enough that JSON's slightly noisier syntax doesn't hurt readability much — while keeping the dep graph leaner.

4. Why no bundled defaults. An earlier draft shipped crates/arnes-core/data/pricing.json via include_str! with seed entries for Gemini and Ollama. Two reasons we dropped it:

  • Pricing data ages out. Bundling means the binary commits to whatever rates we shipped on release day. Provider rates do change — not weekly, but on a months-to-years cadence — and the failure mode is silent: the harness reports a confidently-wrong cost.
  • ModelCostInfo::Unknown already does the right thing. The whole three-state design was built so we could honestly report "we don't know what this turn cost." Bundling defaults undercuts that — we'd be claiming knowledge we can't actually maintain. With no bundling, fresh installs default to Unknown; users opt in by populating ~/.arnes/pricing.json.

Side benefit: zero maintenance burden, no include_str!, no second source-of-truth file.

5. No I/O, no path resolution. Earlier drafts shipped load_pricing(path) + load_pricing_default() + a LoadError enum splitting I/O errors from parse errors + special-cased "missing file → empty registry" logic. None of that has a caller at M1 — no Session exists yet to consult pricing. The PR that wires the registry into a session will own file-reading, home-dir resolution, and missing-file policy. This PR is a pure function over a &str.

6. parse_pricing shape. Serde does parsing, variant selection, and f64→Micros; the function only has to turn each ProviderBlock into a (String, ProviderPricing) pair and hand the iterator to PricingRegistry::from_providers. The wire shape and the registry's native shape are the same group-by-provider structure, so there's nothing to flatten or regroup. Errors propagate as serde_json::Error — no bespoke error enum because there's nothing to discriminate.

Code skeleton

Modified in crates/arnes-core/src/usage.rs (augment existing types):

use serde::Deserialize;

#[derive(Clone, Debug, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum ModelCostInfo {
    Priced(ModelPricing),
    Free,
    #[serde(skip)]
    Unknown,
}

#[derive(Clone, Debug, Deserialize)]
#[serde(from = "Rates")]
pub struct ModelPricing {
    pub input_per_mtok:       Micros,
    pub output_per_mtok:      Micros,
    pub cache_read_per_mtok:  Option<Micros>,
    pub cache_write_per_mtok: Option<Micros>,
    pub thinking_per_mtok:    Option<Micros>,
}

#[derive(Deserialize)]
struct Rates {
    input_per_mtok:       f64,
    output_per_mtok:      f64,
    cache_read_per_mtok:  Option<f64>,
    cache_write_per_mtok: Option<f64>,
    thinking_per_mtok:    Option<f64>,
}

impl From<Rates> for ModelPricing {
    fn from(r: Rates) -> Self {
        let m = |d: f64| Micros((d * 1_000_000.0).round() as i64);
        ModelPricing {
            input_per_mtok:       m(r.input_per_mtok),
            output_per_mtok:      m(r.output_per_mtok),
            cache_read_per_mtok:  r.cache_read_per_mtok.map(m),
            cache_write_per_mtok: r.cache_write_per_mtok.map(m),
            thinking_per_mtok:    r.thinking_per_mtok.map(m),
        }
    }
}

Appended to crates/arnes-core/src/pricing.rs:

use serde::Deserialize;

/// Parse the on-disk pricing JSON into a `PricingRegistry`. Pure
/// function over the file contents; I/O and path resolution belong to
/// the caller.
pub fn parse_pricing(src: &str) -> Result<PricingRegistry, serde_json::Error> {
    let blocks: Vec<ProviderBlock> = serde_json::from_str(src)?;
    Ok(PricingRegistry::from_providers(blocks.into_iter().map(|b| {
        let models = b.models
            .into_iter()
            .map(|m| (m.id, ModelCostInfo::Priced(m.pricing)))
            .collect();
        (b.provider, ProviderPricing {
            default: b.default.unwrap_or_default(),
            models,
        })
    })))
}

#[derive(Deserialize)]
struct ProviderBlock {
    provider: String,
    default:  Option<ModelCostInfo>,
    #[serde(default)]
    models:   Vec<ModelEntry>,
}

#[derive(Deserialize)]
struct ModelEntry {
    id:      String,
    #[serde(flatten)]
    pricing: ModelPricing,
}

One spot to validate during implementation: #[serde(flatten)] on a field whose type uses #[serde(from = "Rates")]. If it doesn't compose, the fallback is to nest one level — { "id": "flash", "pricing": { "input_per_mtok": ... } } in the JSON, drop the flatten attribute on ModelEntry.

lib.rs additions

pub use pricing::parse_pricing;

(PricingRegistry and ProviderPricing are already re-exported from PR #5; ModelCostInfo and ModelPricing from PR #2.)

Tests

All tests run against fixture strings — no filesystem.

  • Well-formed file: a fixture with one paid provider (two models) and one provider with "default": "free" produces a registry that resolves each declared model to Priced and any other model under the free provider to Free.
  • Provider block with only default: resolves any model under that provider to the declared default; declared models on other providers stay Unknown.
  • Provider block with only models: declared models resolve to Priced; undeclared models under the same provider fall through to the default Unknown.
  • Malformed JSON: returns Err(serde_json::Error).
  • Model entry missing input_per_mtok: serde rejects.
  • f64 → Micros conversion: "input_per_mtok": 0.075 in JSON yields a Priced entry whose input_per_mtok is Micros(75).
  • Self-hosted-but-paid provider default: a fixture with "default": {"priced": {"input_per_mtok": 0.05, "output_per_mtok": 0.20}} resolves any model on that provider to Priced at those rates.
